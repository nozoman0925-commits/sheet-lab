# 試験運用計画（5〜10人 × 7日間）

機能の追加をいったん止め、実際の利用者で「続くか」を確かめる。

## 1. 目的

- 初日に一太刀を一つ斬れるか（迷わず使い始められるか）。
- 3日目・7日目に戻ってくるか（続くか）。
- どこで止まったか、なぜ止まったかを知る。

## 2. 参加者

| 項目 | 内容 |
|---|---|
| 人数 | 5〜10人（できれば8人以上） |
| 対象 | 自分を変えたいと思っている男性。年代・生活（学生／会社員／夜勤など）をばらす |
| 端末 | iPhone を半数以上。Android・PC も1人ずつ入れる |
| 除外 | 作り手の身内だけで固めない。少なくとも半数は、アプリを初めて見る人 |
| 同意 | 開始前に「記録の扱い」（後述）を説明し、同意をもらう |

## 3. 配り方

- claude.ai の Artifact の共有リンクを個別に送る（**公開範囲は「リンクを知っている全員」になっている。試験の間だけ、この設定で配る。終わったら見直す**）。
- オフライン版を試す人には、`pwa/` を置いた URL を送り、「共有 → ホーム画面に追加」を案内する。
- 説明は最小限にする（「毎日開いて、出てきたことをやってみてください」だけ）。迷った所こそ知りたい。

## 4. 測る数字

アプリは外部に記録を送らないため、数字は**参加者の自己申告**と、**最終日に書き出してもらう記録**（誓いの間 →「記録を書き出す」）から集める。記録の提出は任意とし、写真は含めない。

| 指標 | 定義 | 目標（目安） |
|---|---|---|
| 初回完了率 | 入門を終え、初日に一太刀を「斬った」人の割合 | 80%以上 |
| 序章の離脱 | 序章の途中で閉じて、戻らなかった人数 | 0〜1人 |
| 入門の所要時間 | 序章の開始から道場に着くまで（自己申告でよい） | 5分以内 |
| 3日目継続率 | 3日目にも記録がある人の割合 | 60%以上 |
| 7日目継続率 | 7日目にも記録がある人の割合 | 40%以上 |
| 一太刀の達成率 | 記録した日のうち「斬った」日の割合 | 50〜80%（高すぎれば易しすぎ） |
| 未達の理由 | 「斬れなかった理由」の内訳 | 偏りを見る |
| 迷った回数 | 「どこを押せばいいか分からなかった」場面の数 | 一人あたり2回以下 |

## 5. 日ごとの進め方

| 日 | 作り手がすること | 参加者に聞くこと（1〜2問だけ） |
|---|---|---|
| 0日目 | リンクを送る。同意をもらう | — |
| 1日目 夜 | 一言だけ連絡 | 「今日の一太刀は斬れた？迷った所はあった？」 |
| 3日目 夜 | 一言だけ連絡 | 「今日も開いた？開かなかったなら、なぜ？」 |
| 5日目 | 連絡しない（自然に続くかを見る） | — |
| 7日目 | 終了の連絡。記録の書き出し（任意）を頼む | 下の聞き取り |

## 6. 最終日の聞き取り（10分）

1. このアプリを一言で言うと？
2. 一番よかった場面は？一番いやだった場面は？
3. 一太刀は、難しすぎた／易しすぎた／ちょうどよかった？
4. 師範の言葉はどう感じた？（励み／うるさい／気にならない）
5. 序章とチュートリアルは長かった？短かった？
6. 文字は読みやすかった？押しにくいボタンはあった？
7. 明日からも使う？使わないなら、何があれば使う？
8. 体や心の状態を聞かれて、不快だったことは？

## 7. 記録の扱い（参加者への説明）

- 記録はあなたの端末（またはあなたの claude.ai の保存領域）にだけあり、作り手には自動で届かない。
- 提出は任意。提出するのは書き出したファイルだけで、写真は含めない。
- 提出された記録は分析だけに使い、名前を外して扱い、試験の終了後3か月以内に消す。
- 体調・気分の答え（睡眠・ストレス・気分の落ち込みなど）は、とくに慎重に扱う。

## 8. 判断の目安

- 初回完了率が低い → 序章・入門・チュートリアルの長さと分かりやすさを直す。
- 3日目で大きく落ちる → 2日目に開く理由（通知・前日の続き・師範の一言）を見直す。
- 達成率が9割を超える → 一太刀が易しすぎる。3割を下回る → 難しすぎる（課題の難度表を見直す）。
- 「うるさい」が多い → 師範の台詞の出る回数を減らす。

## 9. 結果の記録

結果は `docs/試験運用_結果.md` にまとめ、直すことを優先順に並べる。直すまでは新しい機能を足さない。
