# セキュリティ点検の結果（第27版 → 第28版で修正）

- 点検日：2026-11-18
- 対象：`bushido.html`（`src/` から組み立てたもの）と `pwa/sw.js`
- 方法：ソースを読み、手元だけで動かして確かめた（ローカルのサーバー・ダミーの記録・外部への通信なし）
- 範囲：**このアプリの境目に絞った点検**。セキュリティ監査スキルの「完全監査」（6段階・複数の点検役による網羅）は行っていない。完全な網羅とは言えない。

## このアプリの「境目」

1ファイルで動き、運営者のサーバーを持たないアプリなので、境目は少ない。

| 境目 | 低い信頼の側 | 守るもの |
|---|---|---|
| 記録ファイルの読み込み | **他人から渡されたファイル** | 利用者の画面・記録・claude.ai の保存領域 |
| 共有リンク | リンクを開いたほかの人 | 利用者それぞれの記録 |
| オフライン版のキャッシュ | 同じサイトの他のページ | 本体の中身 |
| 外部への送信 | 外部のサービス | 記録・写真 |

## 見つかったこと

### 1. 【修正済み・重要度：中】読み込んだファイルの文字が、画面の中で命令として動いた

- **内容**：誓いの間の「記録を読み込む」で読み込んだ JSON の値（修行の `id` や `status`、師範の `motive` など）が、画面を組み立てる時にエスケープされずに HTML へ差し込まれていた。他人が細工したファイルを「これ、私の記録。読み込んでみて」などと渡すと、読み込んだ人の画面の中で、細工した人の書いた命令が動く。
- **起きうること**：命令は、読み込んだ人のアプリの中で動く。その人の記録や写真を読める。ただし、外へ送るには claude.ai の通信の制限をすり抜ける必要があり、それは確かめていない。最悪の場合は記録・写真が漏れる、と考えて扱う。
- **前提**：利用者が自分で、他人のファイルを選んで「置き換える」を押すこと。
- **確かめ方**：日付以外の全358か所の文字列に命令を仕込んだファイルを作り、第27版で読み込んだ。4か所（`tasks[].id`・`tasks[].status`）で命令が動いた。
- **直し方（第28版）**：読み込みの入口 `importPreview`（`src/js/10-screens.js`）で、ファイルの中身を `importClean` に通すようにした。
  - 文字列とキーの `< > " ' `` を全角に置き換える。
  - 日付の形でない「日」のキーを捨てる。
  - `__proto__`・`constructor`・`prototype` のキーを捨てる。

  入口は一つだけなので、画面ごとの差し込み口（数十か所）を個別に直すより漏れがない。利用者自身の文章に半角の引用符があった場合、読み込むと全角になる。
- **再発防止**：`tests/t28.js` を足した。修正前の版では不合格、修正後は合格することを確かめた。

### 2. 【残っている・重要度：低】壊れた値の入ったファイルを読み込むと、画面の一部が表示されなくなる

- 型の合わない値（例：分野の番号が文字列）を含むファイルを読み込むと、表示の途中でエラーが出る。命令が動くことはない。
- 元に戻すには、正しい控えを読み込み直すか、「すべての記録を消去」を使う。
- 直すなら：`importPreview` で、主な項目の型（`tasks` が配列、`cat` が数値など）を確かめ、合わないファイルを断る。

### 3. 【確認が必要】共有リンクで開いた人どうしの記録

- アプリは記録を claude.ai の保存領域の `data/users/<その人のID>/` に書く。公開の時に、保存領域の規則を何も足していない（`db: {}`）。
- claude.ai の仕様では、この場所は**本人だけが読み書きできる**のが既定。だから、リンクを開いた人どうしで記録は見えない、と読める。
- ただし、実際の動きは claude.ai 側にあり、このリポジトリからは確かめられない。**2つのアカウントで同じリンクを開き、片方の記録がもう片方に見えないこと**を、一度確かめること。
- 今の公開範囲は「リンクを知っている全員」。試験運用の後は、配る相手を絞る設定にするか見直す（設定は Artifact の「共有」から。運営者が自分で変える必要がある）。

### 4. 【問題なし】そのほか

- **外部への送信**：アプリから外へ出る通信は、Google Fonts（書体）の読み込みだけ。記録・写真を送る処理はない（`fetch`・`XMLHttpRequest`・`sendBeacon` を使っていない）。
- **写真**：写真はファイルの書き出しに含めず、読み込みでも復元しない。AI に送る処理はない。
- **オフライン版のキャッシュ（`sw.js`）**：同じサイトの GET だけを保存する。書体だけは Google から取り、手元に保存する。他人の入力でキャッシュの中身が変わる経路はない。
- **ブラウザ内の保存（`localStorage`）**：同じ端末・同じサイトの中だけで、アプリ自身が書いた値。境目をまたがない。

## 次にすること

1. 共有リンクでの記録の分かれ方を、2つのアカウントで確かめる（上の 3）。
2. 読み込みで型も確かめる（上の 2）。
3. 大きく作りを変える時（通知のサーバー・アプリストア）は、点検をやり直す。
