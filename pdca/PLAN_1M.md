# 月100万円計画(2026-10-13 オーナー方針)
方針: 人間の作業は1日10分以内で、月の売上100万円を目指す。運営(商品づくり・記事・改善・返信案)はAIが行う。

## 目標
- 月の売上100万円。人間の作業は1日10分以内。
- 数字は保証ではなく目標。下の見込みはすべて仮説で、実績(pdca/INBOX.md)が出たら置き換える。

## KPIの式
売上 = 月の訪問数 × 購入率 × 平均単価 + 定額ツールの会員数 × 月額

## 目安の数字(仮説)
| 案 | 内訳 | 売上 |
|---|---|---|
| 案A | 月30万PV × 購入率0.3% × 平均単価1,100円 | 約99万円 |
| 案B | 月10万PV × 0.3% × 1,500円 = 45万円 + 定額ツール(月980円)× 560人 | 約100万円 |

途中の目標(仮説):
| 時期 | 目標 |
|---|---|
| 1か月目 | 初売上 |
| 3か月目 | 月5万円 |
| 6か月目 | 月30万円 |
| 12か月目 | 月100万円 |

## 4本柱
1. **商品**: 業界特化テンプレートを1日2本つくる(PRODUCTS.md、優先度G)。10〜20本ごとにまとめ売りセットにする。
2. **集客**: サイト記事は1日2本まで(検証済みのみ)。note無料記事を1日1本(オーナーが貼る)。Pinterest。はてなブログは設定後。
3. **単価**: 業界セット9,800円。定額ツールは、リポジトリの非公開化と決済設定の後。
4. **改善**: お客様の声 → 改善 → 無料で再ダウンロード。

## 人間の10分の内訳(1日)
| 作業 | 時間 |
|---|---|
| 朝のカレンダー通知を見る | 1分 |
| noteに1本貼る | 2分 |
| AIとの会話で「出品して」と送る | 1分 |
| お客様への返信案を確認して送る | 3分 |
| 数字を1つ報告する(PVやnoteのビュー) | 3分 |

初回のみの設定作業(ネットワーク許可、トークン設定、はてなブログ、Pinterest)は HUMAN_TASKS.md に別枠で書く。

## 週次で見る数字と直す場所
| 見る数字 | 低いときに直す場所 |
|---|---|
| PV(訪問数) | 記事とnote(テーマ、題名、本数) |
| 購入率 | 商品ページと画像(説明、検証記録、サムネイル) |
| 平均単価 | セット化(業界セット、関連商品の導線) |

## 判断ルール(2026-10-13追加)
オーナー判断: 「原稿の量より先に、集客→購入→利益を計測できる状態にする」。計測は pdca/METRICS.md。
- (a) ボトルネックの順は ①集客(見つけてもらう)→ ②無料で役立つ → ③購入 → ④分析。現状は無料お試し版もダウンロード0のため、①集客が最大のボトルネック。
- (b) 300円noteは主力ではなく集客商品として評価する。指標は、noteからBOOTHへのクリックと購入。
- (c) noteは問題の解き方、BOOTHは完成品のテンプレートと役割を分け、同じ内容の使い回しをしない。
- (d) 週次レビューで METRICS.md を更新し、続ける・やめる・始めるを各最大1つ決める。公開から4週で閲覧も販売も無い商品は、タイトル・画像・タグの改善対象にし、同じ型の商品の追加を止める。
- (e) 集客の計測には Cloudflare Web Analytics のトークン設定(人間の初回作業)が最優先。サイトの商品リンクに ?from=<記事slug> のような参照元が分かる工夫ができるか検討する。ただし、BOOTH側でその参照元を販売者が見られるかは未確認。見られない場合は「BOOTH側では参照元別の計測ができない」という事実をここに書き、サイト側のPVとBOOTHの販売数を週単位で突き合わせるにとどめる。
