# 仕様: 原価計算表(メニュー別の原価率・粗利) slug: menu-cost
作成: 2026-10-13(クラウド側AI) / 事業G(業界特化・業界=飲食・想定価格=1,980円) / 種類: **xlsx**(マクロなし・動的配列なし・LET/LAMBDAなし)
作るのはオーナーPCのローカルClaude(Microsoft Excelで作成・検証)。販売用ファイルはリポジトリが公開の間は置かない。税・法令の判断はしない(消費税の扱い、食品表示、価格設定の助言は扱わない。入力された金額と数量から原価率と粗利を計算するだけ。販売価格は「お客様が決めた価格をそのまま入力」し、税込・税抜は使う人が統一する)。

## 商品名案・想定ユーザー
- 商品名案: 「飲食店向け 原価計算表(メニュー別の原価率・粗利を自動計算)｜材料100種・メニュー20品・マクロなし Excel」
- 想定ユーザー: 個人経営の飲食店・カフェ。仕入れ値から1食あたりの原価を出し、目標の原価率を超えるメニューを見つけたい人。飲食セット(想定9,800円)の1本目の候補。

## シート構成(4枚)
1. 「使い方」: 入力する場所(薄い色)、材料の単位の決め方(g・個・mlなどを使う人が統一)、レシピの書き方、目標原価率の入れ方、限界、入力例の消し方。
2. 「材料」(5〜104行=100種): A 材料名(入力) / B 仕入れ数量(入力。例 1000。単位は使う人が統一) / C 仕入れ価格(入力。円) / D 単価(数式) / E 点検(数式)
3. 「レシピ」(5〜304行=300行): A メニュー名(入力。メニューのA列と同じ文字) / B 材料名(入力。材料のA列と同じ文字。入力規則で材料A5:A104のリストから選ぶ) / C 使用量(入力。材料の仕入れ数量と同じ単位) / D 該当数(数式) / E 原価(数式)
4. 「メニュー」(5〜24行=20品): A メニュー名(入力) / B 販売価格(入力。円) / C 原価(数式) / D 要確認件数(数式) / E 粗利(数式) / F 原価率(数式) / G 判定(数式)。B2 = 目標原価率(入力。例 0.35)

## 数式(Excel関数名。完全一致はSUMPRODUCT。SUMIFS/COUNTIF/MATCHは名前に「*」「?」「~」が入るとワイルドカード扱いになるため、名前の突き合わせには使わない)
5行目の例(各範囲の最終行までコピー):
| セル | 数式 |
|---|---|
| 材料 D5 単価 | `=IF(A5="","",IF(N(B5)<=0,"",C5/B5))` |
| 材料 E5 点検 | `=IF(A5="","",IF(SUMPRODUCT(--($A$5:$A$104=A5))>1,"重複",IF(N(B5)<=0,"数量0","")))` |
| レシピ D5 該当数 | `=IF(B5="","",SUMPRODUCT(--(材料!$A$5:$A$104=B5)))` |
| レシピ E5 原価 | `=IF(B5="","",IF(D5=0,"材料なし",IF(D5>1,"重複",IF(SUMPRODUCT(--(材料!$A$5:$A$104=B5),--(材料!$E$5:$E$104="数量0"))>0,"数量0",N(C5)*SUMPRODUCT(--(材料!$A$5:$A$104=B5),材料!$D$5:$D$104)))))` |
| メニュー C5 原価 | `=IF(A5="","",SUMPRODUCT(--(レシピ!$A$5:$A$304=A5),レシピ!$E$5:$E$304))`(文字の原価は0として扱われ、合計に入らない) |
| メニュー D5 要確認件数 | `=IF(A5="","",SUMPRODUCT(--(レシピ!$A$5:$A$304=A5),--ISTEXT(レシピ!$E$5:$E$304)))` |
| メニュー E5 粗利 | `=IF(A5="","",N(B5)-C5)` |
| メニュー F5 原価率 | `=IF(A5="","",IF(N(B5)>0,C5/B5,""))` |
| メニュー G5 判定 | `=IF(A5="","",IF(D5>0,"要確認",IF(F5="","価格なし",IF(F5>$B$2,"目標超過","OK"))))` |
原価率が目標「ちょうど」のときはOK(超過は「目標より大きい」場合のみ)。要確認のメニューは、材料なし・重複・数量0の行があり、原価が不完全な可能性があるため原価率を信用しない(判定を要確認にする)。
条件付き書式: G列「目標超過」=赤、「要確認」=黄、「価格なし」=灰。

## 印刷設定
- 「メニュー」: A4縦 / 印刷範囲 A1:G24 / 横1ページに収める。「材料」「レシピ」は印刷対象外(必要なら使い方に手順を書く)。
- 画面表示: 各シートの見出し行(4行目)を固定。

## 検証ケース(私がLibreOfficeで同じ式を試作して再計算し、ケース1〜10の期待値と一致を確認済み。最終確認はExcelで)
材料: 鶏もも肉(1000g・800円→0.8)/ 米(5000g・2500円→0.5)/ 玉ねぎ(1000g・300円→0.3)/ 卵(10個・280円→28)/ A*(100・100円→1)/ ゼロ(数量0・100円)/ 米粉(1000・600円→0.6)。目標原価率 0.35。

|---|---|---|
| 1 | 親子丼(販売900): 鶏150g・玉ねぎ50g・卵2個・米200g | 原価=120+15+56+100=291、粗利=609、原価率≒0.3233、判定=OK |
| 2(境界) | 境界A(販売1000): 鶏437.5g | 原価=350、原価率=0.35、判定=OK(目標ちょうどは超過にしない) |
| 3(境界) | 境界B(販売1000): 鶏438.75g | 原価=351、原価率=0.351、判定=目標超過 |
| 4 | 材料表にない名前「ぶた」を使うレシピ行 | その行の原価=「材料なし」、メニュー(未登録丼)の原価=80(材料なしの行は含めない)、要確認件数=1、判定=要確認 |
| 5(境界) | 仕入れ数量が0の材料「ゼロ」を使う | 材料の単価=空欄、点検=「数量0」、レシピの原価=「数量0」、メニューの判定=要確認 |
| 6(境界) | 材料名に「A*」(ワイルドカード文字) | 「A*」のレシピ行の原価=50(使用量50×単価1)。他の材料を巻き込まない |
| 7 | 使用量0 | 原価=0(エラーなし) |
| 8 | 販売価格が0のメニュー | 原価率=空欄、判定=価格なし、エラーなし |
| 9 | 材料表に「米」を2行入力した場合(別試作で確認) | 材料の点検=「重複」(2行とも)、その材料を使うレシピ行=「重複」、メニューの判定=要確認 |
| 10 | 材料に「米粉」(「米」を含む別名) | 「米」のレシピ行が米粉を巻き込まない(完全一致) |
| 11(Excel確認) | 材料・レシピ・メニューを全部空欄にする | 数式がエラーを出さない |
| 12(Excel確認) | 入力規則 | レシピBが材料のリストから選べる、数量・価格は数値のみ |
| 13(印刷確認) | メニューをPDF出力 | A4縦1ページ、A〜G列が切れずに入る |
ケース1〜10はクラウド側のLibreOfficeで確認済み(試作の再計算値)。11〜13はExcelでの手動確認で、ローカル側が行う。「0.35ちょうど」の境界は浮動小数点の扱いがExcelで同じか未確認のため、ケース2もExcelで必ず確認する。
