# 仕様: 出来高管理表(工程ごとの進捗率と出来高金額) slug: progress-billing
作成: 2026-10-13(クラウド側AI) / 事業G(業界特化・業界=建設・リフォーム) / 種類: **xlsx**(マクロなし・動的配列なし)
作るのはオーナーPCのローカルClaude(Microsoft Excelで作成・検証)。販売用ファイルはリポジトリが公開の間は置かない。税・法令の判断はしない(消費税、請求書の要件、工事の会計処理、請負契約上の出来高の認定方法は扱わない。金額は入力された数字をそのまま集計する)。

## 商品名案・想定ユーザー
- 商品名案: 「出来高管理表(工程ごとの進捗率から出来高金額・前回差・未出来高を自動計算)｜工務店・リフォーム業向け Excel(マクロなし・20工程)」
- 想定ユーザー: 工務店・リフォーム業・小規模工事で、1案件を工程に分け、「今どこまで進み、金額にするといくらか」を月ごとに記録したい人。工事台帳(1,980円)・工程表と同じ現場で使えるシリーズ。建設セットの候補。

## シート構成(2枚)
1. 「使い方」: 入力する場所(薄い色)、進捗率の入力ルール(0〜100%)、前回までの出来高の引き継ぎ方、限界。
2. 「出来高」(1案件=1シート。コピーして案件ごとに使う)
   - B2: 契約額(入力。数値)/ B3: 現場名(入力)/ D3: 対象月(入力。日付)
   - 6〜25行=20工程。A: 工程名(入力)/ B: 工程金額(入力。契約額の内訳)/ C: 進捗率(入力。0〜100%)/ E: 前回までの出来高累計(入力。初回は空欄)
   - D・F・G・H は数式。26行が合計行。28〜29行が点検欄。

## 数式(Excel関数名。マクロ・動的配列関数・LET/LAMBDA不使用)
| セル | 数式(6行目の例。25行目までコピー) |
|---|---|
| D6(出来高金額=工程金額×進捗率) | `=IF($A6="","",ROUND(N(B6)*N(C6),0))` |
| F6(今回の出来高=出来高-前回累計) | `=IF($A6="","",D6-N(E6))` |
| G6(未出来高=工程金額-出来高) | `=IF($A6="","",N(B6)-D6)` |
| H6(確認) | `=IF($A6="","",IF(OR(N(C6)<0,N(C6)>1),"進捗率が0〜100%の範囲外",IF(D6<N(E6),"出来高が前回より減っています","")))` |
| B26, D26, E26, F26, G26(合計) | `=SUM(B6:B25)` など(列ごと) |
| C26(全体の進捗率) | `=IF(B26=0,"",ROUND(D26/B26,3))`(表示形式は0.0%) |
| B28(契約額と工程金額合計の差) | `=B2-B26`(0でなければ内訳の入れ忘れ・入れ過ぎ) |
| B29(要確認の工程数) | `=COUNTIF(H6:H25,"?*")` |
端数処理は円未満を四捨五入(ROUND。Excelは5を切り上げ=0.5→1)。切り捨て・切り上げに変えたい場合は使う人が式を変える(商品説明に明記。端数の扱いが契約で決まっている場合はそちらに従う)。
条件付き書式: H列の文字=赤、B28が0以外=オレンジ、F列がマイナス=赤字。

## 印刷設定
- A4横 / 印刷範囲 A1:H29 / 横1ページに収める。1行目と見出し行(5行目)を固定。

## 検証ケース(私がLibreOfficeで同じ式を試作して再計算し、ケース1〜10の期待値と一致を確認済み。最終確認はExcelで)
入力: 工程7件(工程金額/進捗率/前回累計)=基礎 1,000,000/100%/800,000、躯体 3,000,000/33.3%/0、端数 1,000,001/33.3%/0、半端 5/50%/0、空欄進捗 300,000/空欄/0、範囲外 100,000/110%/0、戻り 200,000/10%/50,000。契約額B2=5,600,006(工程金額の合計)。
| # | 内容 | 期待値 |
|---|---|---|
| 1 | 進捗100%の工程(基礎) | D=1,000,000、F=200,000、G=0、H=空欄 |
| 2 | 小数の進捗率(躯体 33.3%) | D=999,000、F=999,000、G=2,001,000 |
| 3(境界) | 端数が出る(1,000,001×33.3%=333,000.333) | D=333,000(四捨五入)、G=667,001 |
| 4(境界) | ちょうど0.5円(5×50%=2.5) | D=3(0.5は切り上がる)。Excelでの結果も要確認(ROUNDは同じ動作のはず) |
| 5(境界) | 進捗率が空欄 | D=0、G=工程金額のまま300,000、エラーなし |
| 6(境界) | 進捗率110% | D=110,000は計算されるが、H=「進捗率が0〜100%の範囲外」、G=-10,000 |
| 7(境界) | 出来高が前回累計より小さい(10%=20,000、前回50,000) | F=-30,000、H=「出来高が前回より減っています」 |
| 8 | 合計行 | B26=5,600,006、D26=2,462,003、E26=850,000、F26=1,612,003、G26=3,138,003、C26=44.0% |
| 9 | 点検欄 | B28=0(契約額=工程金額合計)、B29=2(ケース6・7) |
| 10(境界) | 工程名が空の行(8行目以降) | 数式の結果は空欄でエラーなし。契約額を変えるとB28に差が出る |
| 11(Excel確認) | 全工程・契約額を空欄にする | エラーなし、合計行0、C26空欄 |
| 12(Excel確認) | 入力規則 | Cは0〜1の小数のみ、B・Eは数値のみ |
| 13(印刷確認) | PDF出力 | A4横1ページ、A〜H列が切れずに入る、倍率を記録 |
ケース1〜10はクラウド側のLibreOfficeで確認済み(ケース10は空行の式のみ確認)。11〜13はExcelでの手動確認で、ローカル側が行う。
