# 仕様: 工事台帳(案件別の契約額・原価・入金の管理表) slug: construction-ledger
作成: 2026-10-13(クラウド側AI) / 事業G(業界特化・業界=建設・リフォーム) / 種類: **xlsx**(マクロなし・動的配列なし)
作るのはオーナーPCのローカルClaude(Microsoft Excelで作成・検証)。販売用ファイルはリポジトリが公開の間は置かない。税・法令の判断はしない(消費税の区分、工事進行基準などの会計処理は扱わない。金額は入力された数字をそのまま集計する)。

## 商品名案・想定ユーザー
- 商品名案: 「工事台帳(案件別の契約額・原価・入金・粗利を自動集計)｜工務店・リフォーム業・一人親方向け Excel(マクロなし・20案件)」
- 想定ユーザー: 工務店・リフォーム業・一人親方で、案件ごとに「いくら受注して、いくら原価がかかり、いくら入金されたか」を1枚で把握したい人。見積書(980円)、工程表(仕様作成済み)と同じ現場で使えるシリーズ。建設セット(9,800円)の3本目の候補。

## シート構成(3枚)
1. 「使い方」: 入力する場所(薄い色)、案件Noの決め方、区分の入力ルール、限界、入力例の消し方。
2. 「台帳」(案件一覧。1案件=1行。5〜24行=20案件)
   - A5〜A24: 案件No(入力。例 A-001)/ B: 現場名(入力)/ C: 顧客名(入力)/ D: 契約額(入力。数値)/ E: 着工日(入力。日付)/ F: 完了日(入力。日付)
   - G〜M: 数式(下表)。26行が合計行。28〜29行が点検欄。
3. 「明細」(原価と入金の入力。5〜304行=300件)
   - A: 日付 / B: 案件No(台帳のA列と同じ文字を入力。入力規則で台帳A5:A24のリストから選ぶ) / C: 区分(入力規則のリスト「原価,入金」) / D: 内容(メモ) / E: 金額(数値) / F: 確認(数式)
   - 返金や値引きの調整は、金額にマイナスを入力する。

## 数式(Excel関数名。マクロ・動的配列関数・LET/LAMBDA不使用。完全一致はSUMPRODUCT)
SUMIFS/COUNTIFは案件Noに「*」「?」「~」が含まれるとワイルドカード扱いになるため使わず、SUMPRODUCTで完全一致にする。
| セル | 数式(5行目の例。24行までコピー) |
|---|---|
| 台帳 G5(原価合計) | `=IF($A5="","",SUMPRODUCT(--(明細!$B$5:$B$304=$A5),--(明細!$C$5:$C$304="原価"),明細!$E$5:$E$304))` |
| 台帳 H5(入金合計) | `=IF($A5="","",SUMPRODUCT(--(明細!$B$5:$B$304=$A5),--(明細!$C$5:$C$304="入金"),明細!$E$5:$E$304))` |
| 台帳 I5(粗利=契約額-原価) | `=IF($A5="","",N(D5)-G5)` |
| 台帳 J5(粗利率) | `=IF(OR($A5="",N(D5)=0),"",ROUND(I5/D5,3))`(表示形式は0.0%) |
| 台帳 K5(未入金額=契約額-入金) | `=IF($A5="","",N(D5)-H5)` |
| 台帳 L5(状況) | `=IF($A5="","",IF(F5<>"",IF(K5<=0,"完了・入金済","完了・未入金あり"),IF(E5="","未着工","工事中")))` |
| 台帳 M5(案件No点検) | `=IF($A5="","",IF(SUMPRODUCT(--($A$5:$A$24=$A5))>1,"案件No重複",""))` |
| 台帳 D26, G26, H26, I26, K26(合計) | `=SUM(D5:D24)` など(列ごと) |
| 台帳 J26 | `=IF(D26=0,"",ROUND(I26/D26,3))` |
| 台帳 B28(重複している行数) | `=COUNTIF(M5:M24,"案件No重複")` |
| 台帳 B29(明細の要確認件数) | `=COUNTIF(明細!F5:F304,"?*")` |
| 明細 F5 | `=IF(B5="","",IF(SUMPRODUCT(--(台帳!$A$5:$A$24=B5))=0,"案件Noが台帳にありません",IF(AND(C5<>"原価",C5<>"入金"),"区分を確認","")))` |
注意: 案件Noの比較は大文字・小文字を区別しない(A-001 と a-001 は同じ扱い。下のケース4)。金額欄の文字(「abc」など)は0として扱われ、エラーにはならないが集計されない(入力規則で数値のみにする)。
条件付き書式: 粗利が0未満の行=赤字、L列が「完了・未入金あり」=オレンジ、M列・明細F列の文字=赤。

## 印刷設定
- 「台帳」: A4横 / 印刷範囲 A1:M29 / 横1ページに収める。「明細」は印刷対象外(必要なら使う人が設定)。
- 画面表示: 1行目を固定。台帳の見出し行(4行目)を固定。

## 検証ケース(私がLibreOfficeで同じ式を試作して再計算し、ケース1〜10の期待値と一致を確認済み。最終確認はExcelで)
台帳に入力する5件(契約額/着工/完了): A-001 田中邸 2,000,000 着工10/1 完了なし / A-002 鈴木邸 1,000,000 10/5〜10/30 / A-* ワイルド 100,000 日付なし / A-001 重複行 1 日付なし / B-003 契約額なし 着工11/1 / B-004 500,000 9/1〜9/20。明細は11件(下表)。
| # | 内容 | 期待値 |
|---|---|---|
| 1 | A-001の原価(300,000+200,000+小文字a-001の1,000) | G=501,000(ケース4も含む) |
| 2 | A-001の入金(500,000 と -50,000) | H=450,000(マイナス入力が差し引かれる) |
| 3 | A-001の粗利・粗利率・未入金 | I=1,499,000、J=75.0%、K=1,550,000、状況=工事中(着工あり・完了なし) |
| 4(境界) | 小文字「a-001」の明細 | A-001と同じ案件に集計される(大文字小文字を区別しない)。商品説明と使い方に明記 |
| 5(境界) | 案件No「A-*」(ワイルドカード文字) | G=777のみ(「A-001」「A-002」の原価を巻き込まない)、状況=未着工 |
| 6 | A-002の原価1,100,000と入金1,000,000、完了日あり | I=-100,000、J=-10.0%(赤字表示)、K=0、状況=完了・入金済 |
| 7(境界) | 契約額が空欄のB-003 | D空欄でもエラーなし。G=0、H=0、I=0、J=空欄(0除算を避ける)、K=0、状況=工事中 |
| 8(境界) | 完了日ありで入金ゼロのB-004(契約額500,000) | G=0、H=0、I=500,000、J=100.0%、K=500,000、状況=完了・未入金あり |
| 9 | 案件Noの重複(A-001が2行) | M列に「案件No重複」が2行に出る。B28=2。重複行にも同じ集計値が出て合計行が二重になるため、点検欄で気づけるようにする(合計の自動補正はしない) |
| 10 | 明細の確認列 | 台帳にない「X-999」=「案件Noが台帳にありません」、区分が「返金」=「区分を確認」、正常行は空欄。B29=2。金額が文字「abc」の行はG・Hに加算されない(エラー表示なし) |
| 11(合計) | 上記の台帳合計(重複行を含む) | D26=3,600,001、G26=2,102,777、H26=1,900,000、I26=1,497,224、J26=41.6%、K26=1,700,001(LibreOffice試作の値。重複行を消した場合は再計算して別の値になる) |
| 12(Excel確認) | 全案件・全明細を空欄にする | 数式がエラーを出さず、合計行が0、点検欄が0 |
| 13(Excel確認) | 入力規則 | 明細Bが台帳のリストから選べる、Cは原価/入金のみ、Eは数値のみ |
| 14(印刷確認) | 台帳をPDF出力 | A4横1ページ、全列(A〜M)が切れずに入る、倍率を記録 |
ケース1〜10はクラウド側のLibreOfficeで確認済み(ケース11は試作の実測値)。12〜14はExcelでの手動確認で、ローカル側が行う。最終確認はすべてExcelで行う。

## できないこと
- 消費税の区分、課税・非課税の判定、インボイス要件の確認、工事の会計処理(完成基準・進行基準など)、源泉徴収。
- 21案件以上、明細301件以上(増やしたいときは行を足すか、別ファイルに分ける運用)。
- 案件Noの重複の自動修正、複数ユーザーの同時編集、請求書の発行(請求書は別商品)。
- 見積書ファイルとの自動連携(契約額は手入力)。
- Excel for Mac・ブラウザ版・スマホアプリでの動作は確認するまで「未確認」と書く。
