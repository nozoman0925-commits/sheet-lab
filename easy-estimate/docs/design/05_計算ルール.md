# 05 計算ルール（見積・請求・入金）

仕様書7-5「端数処理、税区分、値引きの計算順序をシステム全体で統一する」を具体化する。
この章のルールは `packages/engine` に1か所だけ実装し、画面・サーバー・PDF・テストがすべて同じコードを使う。

## 1. 大原則
- 金額は円の整数。数量は小数3桁まで。計算途中も整数演算（浮動小数を使わない）
- 単価は商品・工事単価マスタから取り、見積明細には「採用時の単価・原価・価格ID」を写して保存する。マスタが後で変わっても過去の見積は変わらない
- 金額を手で上書きする欄は作らない。調整は「値引き行」「端数調整行」という**種類の決まった行**で行い、計算に組み込む
- 保存・確定時はサーバーが再計算し、画面から送られた金額は使わない
- 販売・原価・粗利・消費税は別々の値として持ち、混ぜない

## 2. 見積の計算順序
```
① 明細行        金額 = 端数処理(数量 × 販売単価)        原価 = 端数処理(数量 × 原価単価)
② 見出し小計     見出しに属する明細の合計（表示用。税計算には使わない）
③ 諸経費行       金額 = 端数処理(対象額 × 率)            対象額 = 指定範囲の明細合計（税率区分ごと）
④ 値引き行       定額：指定の税率区分から差し引く
                 定率：税率区分ごとに 端数処理(対象額 × 率) を差し引く
⑤ 端数調整行     税抜合計を「千円未満切り捨て」などのルールで丸めた差額（マイナス）
⑥ 税抜合計       税率区分ごとに ①＋③−④−⑤
⑦ 消費税         税率区分ごとに 端数処理(税抜合計 × 税率) ※1書類につき税率ごとに1回（インボイス）
⑧ 税込合計       ⑥＋⑦
⑨ 原価合計       ①の原価＋③の原価（諸経費に原価を持たせる場合のみ）。値引き・端数調整は原価を変えない
⑩ 粗利           ⑥の合計 − ⑨     粗利率 = 粗利 ÷ ⑥の合計
```
- **値引き・端数調整は必ず税率区分を持つ**（インボイスの「税率ごとに区分した対価の額」を正しく出すため）。税率が混在する書類の端数調整は、金額が最も大きい税率区分に寄せ、PDF にその旨を出す
- 「一式」で原価内訳のない明細は送信前チェックで警告する

## 3. 端数処理の設定（**未決3**：社内ルールを決めてください）
| 対象 | 選択肢 | 初期値（案） |
|---|---|---|
| ① 明細金額 | 切り捨て／四捨五入／切り上げ | 四捨五入（現行 EASY ESTIMATE と同じ） |
| ③ 諸経費 | 同上 | 切り捨て |
| ④ 定率値引き | 同上 | 切り上げ（値引き額を多めに＝お客様に不利にならない） |
| ⑤ 端数調整 | なし／百円未満切り捨て／千円未満切り捨て／万円未満切り捨て | なし（書類ごとに選択） |
| ⑦ 消費税 | 切り捨て／四捨五入／切り上げ | 切り捨て |

- 設定は組織ごと。変更は履歴に残る
- 書類を確定（提出・発行）した時点の設定を `rules_snapshot` に保存し、その書類は以後その設定で計算する

## 4. 目標粗利率からの逆算（仕様書7-3）
- 「原価合計」と「目標粗利率」から、必要な税抜販売額 = 原価 ÷ (1 − 目標率) を計算し、**今の見積との差額を表示するだけ**
- 反映方法は2つから選ぶ：(a) マスタの単価を改定する（以後の見積に効く）、(b) その見積に値引き行／諸経費行を入れる
- 明細の単価を直接書き換える方式は取らない（**確認したい点**：見積ごとに単価を変えたい運用があるか。ある場合は「単価変更行（理由必須・承認対象）」として設計を足す）

## 5. 複数プラン（A／B／C案）
- 1つの見積に複数の版（plan_label）を持たせ、プランごとに独立して計算
- 比較表：プランごとの税込合計・税抜・粗利・主な差分明細を横に並べる
- 受注したプランの版だけが契約・請求に進む

## 6. 見積 → 契約 → 請求
- 契約は「受注した見積の確定版」から作る。契約金額＝その版の税込合計（再入力しない）
- 追加工事・変更は「追加見積／変更見積」を作り、承諾書（契約書類）を経て、元の契約と別の請求にする

### 分割請求（着手金・中間金・完了金）
```
1. 契約の税率区分ごとの税抜合計を、回ごとの割合で分ける：各回の税抜 = 切り捨て(税抜合計 × 割合)
2. 最終回の税抜 = 税抜合計 − それまでの回の合計（端数はすべて最終回に寄せる）
3. 各回の請求書は、それぞれ1枚の適格請求書として 消費税 = 端数処理(その回の税抜 × 税率) を計算する
```
- この方式だと「各回の消費税の合計」と「契約時の消費税」が数円ずれることがある（各請求書で端数処理するため）。差額は請求一覧の「請求合計と契約金額の差額」に表示し、ずれの理由を明示する
- **未決4**：上記（税抜で割って各回で税計算・推奨）でよいか。別案は「最終回の消費税で差額を吸収して契約時の税額に合わせる」だが、最終回の請求書の税額が『税抜×税率』と一致しなくなる

## 7. 入金・消込
- 入金は請求書に紐づけて登録。1請求に複数回の入金（一部入金）可
- 請求の状態：未入金 → 一部入金 → 入金済。請求額を超える入金は「過入金」として警告し、自動では次の請求へ回さない
- 振込手数料を差し引かれた入金は「手数料（当方負担）」として差額を記録できる（**確認したい点**：手数料をどちらの負担とする運用か）
- 入金予定日を過ぎた未入金はアラート（ホームと通知）

## 8. テストで必ず確認する計算例（抜粋）
| ケース | 期待 |
|---|---|
| 1.15 × 100円（浮動小数で誤差が出る値） | 115円 |
| 10% 対象 105円＋105円 | 消費税 21円（行ごとに計算した 20円 にならない） |
| 8% 対象 999円 | 消費税 79円（切り捨て） |
| 10% と 8% が混在、定率5%値引き | 値引きが税率区分ごとに計算され、税額も区分ごと |
| 千円未満切り捨て（税抜 1,234,567円） | 調整 −567円、税抜 1,234,000円 |
| 諸経費率 8%（対象 1,000,005円） | 80,000円（切り捨て） |
| 分割 30% / 40% / 30%（税抜 1,000,001円） | 300,000 / 400,000 / 300,001 |
| 確定後に端数設定を変更 | 確定済み書類の金額は変わらない |
| 顧客提出用 PDF | 原価・粗利の値が含まれない |
