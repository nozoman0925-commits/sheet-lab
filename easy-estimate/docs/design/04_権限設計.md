# 04 権限設計

## 1. 考え方
権限は「**何に（resource）**・**何を（action）**・**どの範囲で（scope）**」の組み合わせで決める。

- scope：`all`（組織内すべて）／`assigned`（自分が案件メンバーの案件だけ）／`own`（自分が作ったものだけ）／`none`
- 金額は「見える列」を別に制御する：`price`（販売額）／`cost`（原価・仕入価格）／`profit`（粗利・粗利率）
- 判定はサーバーで行う。①API で判定 → ②DB の行単位アクセス制御（RLS）でも同じ条件を強制。画面はその結果を表示するだけ
- 原価・粗利を見せないロールには、**API がその列を返さない**（画面で隠すのではない）

## 3. 協力会社の分離（必須ルール）
1. 協力会社ユーザーが見られる案件 = `project_members` に自社が割り当てられた案件 ∩ ログイン中の元請組織
2. 見られる金額 = 自社宛ての発注金額と、自社が提出した請求額だけ。元請の販売価格・原価・粗利・他社の発注額は API が返さない
3. 協力会社Aと協力会社Bが同じ案件にいても、互いの発注・写真・日報・請求は見えない（写真は「元請が共有にした写真」だけ見える）
4. 同じ協力会社が複数の元請と取引していても、ログイン時に元請を選び、元請ごとにデータが混ざらない
5. 契約終了・退職で `organization_members.status = left` にした瞬間から、全 API・ファイル URL が拒否される。発行済みのファイル URL は期限つき（数分）にして長く有効にしない

## 4. 顧客提出用と内部用の分離（仕様書7-5・21-6）
- 書類テンプレートを「顧客提出用」「内部用（原価見積）」に分け、顧客提出用のテンプレートは原価・粗利の列を**参照すらできない**データだけを受け取る（PDF 生成の入力を別の型にする）
- 顧客提出用 PDF の生成前に「原価・粗利の文字列が含まれていない」ことを自動チェックする
- テストで、全書類種類の顧客提出用 PDF に原価が出ないことを確認する（08章）

## 5. 認証
- メール＋パスワード（ハッシュ化は認証基盤に任せる）、パスワード再設定、2段階認証（管理者・経営者は必須を推奨）
- 協力会社・職人は招待リンクから登録（招待の有効期限つき）
- セッションは一定時間で失効、アカウント停止で即時失効
- ログイン履歴・失敗回数の記録、連続失敗で一時ロック
