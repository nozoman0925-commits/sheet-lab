# 03 データベース設計

## 1. 全テーブル共通のルール
| ルール | 内容 |
|---|---|
| 主キー | `id uuid` |
| 組織分離 | 業務データはすべて `organization_id`（元請会社）を持つ。RLS で「自分が所属する組織の行だけ」に絞る |
| 監査列 | `created_at` `created_by` `updated_at` `updated_by` |
| 論理削除 | `deleted_at` `deleted_by`。一覧・検索からは除外、データは残す（仕様書16） |
| 確定済みの保護 | 書類・版は `locked_at` が入ったら UPDATE 禁止（DB トリガーで拒否）。変更は新しい版を作る |
| 金額 | 円の整数 `bigint`。税抜・税込・原価・粗利を別の列で持ち、混同しない（仕様書7-5） |
| 数量 | `numeric(14,3)` |
| 履歴 | 重要な更新は `activity_logs` に「誰が・いつ・何を・前→後」で記録 |
| 番号 | 採番は `number_sequences` テーブルで行ロックして発番（重複・欠番の扱いを固定） |

## 3. 案件ステータスの遷移
仕様書5-2の17状態。許可する遷移を表で持ち、それ以外は API で拒否する（例：「入金完了」から「見積もり作成中」へは戻せない）。失注・中止は理由必須。すべて `project_status_histories` に記録。
一部は書類の操作で自動的に進める（見積を提出→「見積もり提出済み」、契約確定→「契約済み」、全請求が入金済→「入金完了」）。手動で戻す場合は理由必須。
