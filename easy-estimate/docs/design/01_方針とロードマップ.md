# 01 方針とロードマップ

## 1. 今の桜ミツ（旧 EASY ESTIMATE） との関係
| 項目 | 現行の桜ミツ（旧 EASY ESTIMATE）（easy-estimate/） | 業務統合システム（本設計） |
|---|---|---|
| 動く場所 | 1台のPCのブラウザ内（localStorage） | サーバー＋DB。PC・スマホ・協力会社から同じデータを見る |
| 利用者 | 1人 | 社員・協力会社・職人（7ロール） |
| ログイン・権限 | なし | あり（サーバー側で検証） |
| 範囲 | 見積のみ | 顧客〜案件〜見積〜契約〜発注〜施工〜請求〜入金〜支払〜分析 |

**流用するもの**
- 計算エンジン（`js/engine.js`）と送信前チェック（`js/check.js`）の考え方とテスト。TypeScript に移植してサーバーとブラウザの両方で同じコードを使う（05章）
- 明細の構造（マスタID＋数量＋単価＋写し）、発行確定後は書き換え不可・修正は新しい版、というルール
- 画面の見た目（ダーク＋ブルー、サイドバー、カード、マイクロインタラクション）

**流用しないもの**
- localStorage 保存、ハッシュによる画面切り替え、素の JavaScript の画面実装（本番は Next.js＋TypeScript で作り直す）

現行アプリは、本番が動くまでの「お試し・見積専用版」としてそのまま使える。データは JSON で書き出せるので、本番への取り込み口を用意する（R1）。

## 2. 基本方針（仕様書1-2を設計上のルールに言い換え）
| 仕様書の方針 | 設計上のルール |
|---|---|
| 一度登録した情報を何度も入力させない | 書類は案件・顧客・マスタから生成し、項目を手で写さない。変換（見積→契約→請求）は元データを引き継ぐ |
| 案件を中心にすべて紐付ける | 業務データのテーブルはすべて `project_id`（案件に属さないマスタ類を除く）と `organization_id` を持つ |
| 見積から請求まで金額を連動 | 請求明細は見積明細（確定版）の ID を参照して作る。金額は再入力しない |
| 自社と協力会社の情報を分離 | DB の行単位アクセス制御＋API の権限チェックの二重。画面で隠すだけにしない |
| スマホで主要業務を完結 | 写真・日報・ステータス変更・書類閲覧はスマホ専用画面を用意 |
| 過去の案件・単価を資産に | 価格は履歴テーブルで持ち、見積には「その時点の価格」を写して保存 |
| AIなしで成立 | AI 用の差し込み口は「候補を返すだけ」。金額・確定操作には関与させない |
| 操作履歴・変更履歴 | 全更新を `activity_logs` に記録。確定済み書類は版として残す |

## 3. Phase の組み直し（推奨）
仕様書19章は「機能の種類」で Phase を切っているが、20章の完成条件は Phase 1〜5 にまたがる。
**「ひとつの業務の流れが最後まで回る」単位でリリースを切る** と、途中で使い始められて手戻りも少ない。

| リリース | 中身 | 仕様書の Phase | 使い始められること |
|---|---|---|---|
| **R0 設計** | 本設計書、画面の試作、DB の作成スクリプト | — | （レビュー） |
| **R1 社内で見積〜入金** | ログイン、組織、ユーザー・権限、顧客、案件（ステータス履歴）、全体検索、商品・工事単価DB（価格履歴）、見積（階層・諸経費率・値引き・複数プラン・版管理・送信前チェック）、契約書・注文請書、請求（分割・追加工事）、入金・消込、領収書、PDF、操作ログ、バックアップ、基本ダッシュボード | 1・2・3 の一部・6 の入金 | 社員だけで「問い合わせ→見積→契約→請求→入金」を回す |
| **R2 協力会社** | 協力会社登録・招待・専用ログイン、発注書と発注ワークフロー、受注回答、施工報告、請求書提出、支払管理 | 4・6 の支払 | 発注と支払を紙・LINE から移す |
| **R3 現場・スマホ** | 現地調査、写真（分類・書き込み）、採寸、工程表・カレンダー、作業日報、完了報告、引渡、通知 | 5 | 職人・現場がスマホで報告 |
| **R4 経営管理** | 担当者別・カテゴリー別・協力会社別の分析、資金予定、実行予算 vs 実績 | 6 | 数字を見て判断 |
| **R5 拡張** | 電子契約・メール・LINE・会計ソフト連携、他社への提供、AI 拡張 | 7 | — |

> 仕様書20章の「協力会社機能」「スマホでカメラから写真登録」は R2・R3 の完成条件になる。R1 の時点ではスマホ表示崩れなし・書類閲覧まで。**未決2**：この区切りでよいか。

## 4. R1 の完成条件（案）
仕様書20章から R1 に入るもの：
- ログイン・ログアウト、ユーザーごとの権限設定、権限外データの閲覧不可（サーバー側）
- 顧客・案件の登録・編集・検索・紐付け、重複顧客の候補表示
- 見積書・請求書・領収書・契約書（注文請書）の作成と PDF 出力
- 自動計算が正確（05章のテストをすべて通る）
- 書類の編集履歴・版が保存される、確定済みは上書き不可
- 再読み込み・再ログイン・別端末でもデータが消えない
- 操作履歴が残る、バックアップが取得され、復元テストが完了している
- iPhone / Android で表示崩れがなく、書類の閲覧・PDF保存ができる
