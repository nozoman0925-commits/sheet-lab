# 08 テスト計画

仕様書21「実装した機能は、データ登録・編集・削除・再読み込み・権限確認までテストする」を、自動テストで繰り返し確認できる形にする。

## 1. テストの種類
| 種類 | 対象 | 方法 |
|---|---|---|
| 計算 | packages/engine（05章の全ルール） | 単体テスト。05章8節の計算例を全部入れる |
| 権限 | API と DB（RLS）の両方 | ロールごとのテスト用ユーザーで、許可された操作が通り、**許可されない操作が拒否される**ことを確認 |
| 画面の流れ | 主要な業務の流れ | Playwright（PC とスマホ幅） |
| データの保持 | 保存→再読み込み→別端末 | Playwright |
| バックアップ | 取得と復元 | 月1回の手順書と実施記録 |

## 2. 侵入テスト（権限）— 必ず自動化する
| # | 操作 | 期待 |
|---|---|---|
| P1 | 協力会社A のユーザーが、協力会社B だけが割り当てられた案件の ID を直接 API に送る | 403。データは1件も返らない |
| P2 | 協力会社A が自社の発注を取得 | 元請の販売価格・原価・粗利・他社の発注額の列が**レスポンスに含まれない** |
| P3 | 協力会社A が他社の写真ファイルの URL を推測してアクセス | 拒否 |
| P4 | 原価閲覧の許可がない営業が見積を取得 | 原価・粗利の列が含まれない。CSV 出力にも含まれない |
| P5 | 担当外の案件を営業が開く | 拒否（assigned の場合） |
| P6 | 確定済み請求書を API で直接 UPDATE | 拒否（API と DB トリガーの両方） |
| P7 | activity_logs を UPDATE / DELETE | 拒否 |
| P8 | 停止したアカウントの古いセッションで API を呼ぶ | 拒否 |
| P9 | 組織X のユーザーが組織Y の顧客 ID を指定 | 拒否 |
| P10 | 顧客提出用 PDF を全書類種類で生成 | 原価・仕入価格・粗利の値が含まれない |

## 3. 仕様書20章の完成条件との対応（R1 分）
| 完成条件 | テスト |
|---|---|
| ログイン・ログアウト | 正しい／誤ったパスワード、ログアウト後に戻るボタンで見えない |
| ユーザーごとに権限を設定できる | 個別上書きを付けた直後から API の結果が変わる、操作履歴に残る |
| 顧客の登録・編集・検索 | 各項目の保存→再読み込みで一致、電話番号の重複候補が出る、論理削除で一覧から消えデータは残る |
| 案件の登録・編集・検索・紐付け | 案件番号の連番、ステータス変更履歴、許可されない遷移の拒否 |
| 見積書・請求書の作成 | 見積→契約→請求で金額を再入力しない、分割請求の合計と契約額の差額表示 |
| PDF 出力 | A4、ページまたぎで表の見出しを繰り返す、日本語が化けない、インボイス記載事項がある |
| 自動計算が正確 | 05章8節すべて |
| 編集履歴が保存される | 版の作成、差分表示、確定後の上書き拒否 |
| 再読み込みしても消えない | 保存直後のリロード、別ブラウザでのログイン |
| 操作履歴が残る | 作成・更新・削除・出力・権限変更・ログインが記録される |
| バックアップ・復元 | 検証環境に復元して件数とハッシュが一致 |
| スマホで表示崩れがない | iPhone・Android 幅で主要画面のスクリーンショット比較 |

## 4. やってはいけないこと（仕様書21の確認方法）
| 禁止事項 | 確認方法 |
|---|---|
| ダミーデータだけで完成に見せない | 完成判定は空のデータベースから始める E2E で行う |
| 保存されない入力フォーム | 全フォームに「入力→保存→再読み込み→値が一致」のテスト |
| ボタンだけ置いて機能実装としない | 画面上の全ボタンに対応する E2E の操作がある（未実装のボタンは置かない） |
| 見積と請求の二重入力 | 請求画面に金額入力欄が存在しないことをテストで確認 |
