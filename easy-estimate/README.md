# 桜ミツ（OUMITSU）— Phase 1：見積

RENOVATION WORKS MANAGEMENT ／ SMARTER WORK. BETTER BUILD.

（旧名 EASY ESTIMATE。フォルダ名と保存データのキーは、既存データを引き継ぐため `easy-estimate` のまま）

見積書を作るためのパソコン向けアプリです。インストール不要。
`index.html` をブラウザ（Chrome / Edge 推奨）で開くだけで動きます。データはそのパソコンのブラウザ内に保存されます。

## 起動のしかた
- **ふだん使い**：`index.html` をブラウザ（Chrome / Edge 推奨）で開く。見積の作成・PDF出力・テキスト型PDFの読み込みまで、すべて使えます
- **写真・スキャンPDFの文字読み取り（OCR）を使うとき**：ブラウザの安全上の制限で、ファイルを直接開いた状態（`file://`）では OCR の部品を動かせません。次のどちらかで開いてください
  - このフォルダでローカルサーバーを起動して `http://localhost:8000/` を開く（例：`python -m http.server 8000`。Python が入っているPCのみ）
  - 社内サーバーやホスティングに置く（公開はご承認を得てから行います）
- どちらの開き方でも、データと読み込んだファイルはそのPCのブラウザの中だけに保存され、外部には送られません

## 業務自動化（AI非搭載）
AI・外部のAIサービスは一切使っていません（API・利用料なし）。テンプレート・辞書・OCR・計算エンジン・過去データを組み合わせて、手入力を減らします。
どの入り口から始めても、最後は同じ見積データ（マスタID＋数量＋単価）になります。

### かんたん見積もり作成（ホーム・新規作成から）
| 入り口 | しくみ |
|---|---|
| 文章から | 工事項目マスターの名前・**同義語辞書**・工事テンプレートのキーワードと照合（`js/parse.js`）。漢数字・単位（メートル→m、平米→m²、坪→m² など）をそろえ、数量を読む。「高さ1800」などの寸法で規格を選び分ける。文章に無いテンプレートの項目は「不足候補」として示し、読めなかった語句は推測せず一覧に残す（その場で同義語として登録できる） |
| 音声から | 端末の音声入力（スマホのキーボードのマイク、Windows は Win+H、Mac は fn 2回）で文字にし、文章と同じ処理。アプリ自体は録音・送信しない |
| PDFから | テキスト型PDFは文字と位置をそのまま抽出（pdf.js）。画像だけのPDFは端末内でOCR（tesseract.js、日本語＋英数字）。元のPDFと読み取り結果を並べて表示し、明細・数量・単価・合計を確認・修正してから自社の見積書に変換。原本と読み取り結果はこの端末に保存 |
| 写真から | カメラ撮影・画像（JPEG/PNG、HEIC は Safari、TIFF は対応ブラウザ）。回転・傾き補正・明るさ・コントラスト・切り抜きをしてからOCR。複数枚まとめて読める。手書きメモは「読み取った文字を文章として使う」で文章の処理に回せる |
| 過去の見積から | 顧客名・住所・工事カテゴリー・品名・期間・金額で検索し、明細すべて／選んだ明細／カテゴリー単位で流用。数量・諸経費・備考を引き継ぐか選べる。単価は「現在のマスタ」か「当時の単価」を選べ、当時の単価との差を表示 |
| テンプレートから | 工事カテゴリー別（外構・外壁塗装・内装・屋根・水回り・太陽光・蓄電池）の標準明細にチェックを付けるだけ。「参考候補」は最初は外れた状態 |
| 通常入力 | これまでどおり、マスタを検索して明細を追加 |

### 読み込みのルール（`js/docparse.js`）
- 明細の行は右から「金額 → 単価 → 単位 → 数量」の順に読み、残りを品名とする
- 宛名（〜様／御中）、件名、書類番号、日付（和暦も可）、電話、住所、発行元、小計・消費税・合計を読む。読めなかった項目は空のまま
- **数字は書かれているとおりに読み、直さない**。数量×単価と金額が合わない行、書類の小計と明細の合計が合わない場合は印を付けて知らせるだけ
- OCRの信頼度が低い行（70%未満）は黄色で表示。単位が読めなかった行も知らせる
- 自社マスタとは コード一致 → 品名・同義語の一致 で結び付ける。品名の一部だけが一致する場合（例：「ウッドデッキ補修」と「補修」）は自動で結び付けず候補として示す。マスタに無い品目は「新しいマスタとして登録」できる（コード IMP-、原価は未登録）
- 他社の見積書を変換するときは「元の書類の単価」か「自社マスタの単価」を選べる。元の書類の単価を使った行は、送信前チェックで「取り込み元の単価」と表示される
- PDFはJavaScript等を実行しない設定で開き（`isEvalSupported:false`）、ファイルの中身（先頭のバイト）で種類を確かめ、大きさ（PDF 30MB・画像 25MB・先頭10ページ）を制限する

### 工事項目・単価マスター
- 項目：コード、工事カテゴリー、区分、品名、規格、単位、標準数量、販売単価、原価（仕入）、税区分、原価区分（建設業法20条）、仕入先、施工業者、説明、**同義語**、価格の履歴
- 単価を変えると履歴に残る。過去の見積の単価は固定で、マスタを変えても変わらない（送信前チェックで差を知らせ、「最新単価に更新」はユーザーが選ぶ）
- CSVの書き出し・取り込み

### 数量・寸法計算（`js/calc-tool.js`）
- 見積の明細の「計算」ボタン、テンプレートの各行から使う
- 登録済みの計算式：フェンス延長、面積、土間面積、体積、ブロック数量、クロス面積、外壁塗装面積、砂利必要量、材料数量（施工面積÷1単位の施工面積）
- 入力ごとに mm / cm / m を選べる。ロス率（割増）と端数（小数2桁／切り上げ）を式ごとに設定
- 式は四則演算と ceil・floor・round・min・max だけを解釈する専用の計算機で処理（任意のコードは実行しない）。設定・マスタ →「計算式」で追加・編集でき、試しの値で結果を確かめられる

### 計算（諸経費・値引き・端数調整）
- 計算順序は固定：明細 → 諸経費（率） → 値引き（率・額・選んだ行だけ） → 端数調整（100／1,000／10,000円未満切り捨て） → 消費税（税率ごとに1回）
- 率は万分率の整数で持ち、浮動小数を使わない。値引きは税率区分ごとに計算し、インボイスの「税率ごとの対価」を正しく出す
- 金額はサーバー（将来）・画面・PDFで同じ計算エンジンを使う。発行確定した見積は確定時のルールで固定

### 書類作成の操作
- 自動入力：顧客・案件・テンプレートから宛先・件名・現場住所などを入れる
- 定型文：施工条件・注意事項・有効期限・支払条件・工事保証・追加工事・免責・備考を登録し、ワンクリックで挿入
- 一括操作：明細を複数選んで 削除・複製・最新単価に更新・選んだ行に値引き。書類一覧で複数の見積をまとめてPDF
- 自動保存：保存済みの下書きは入力のたびに自動で上書き、新規はこの端末に「入力途中」として一時保存し、次に開いたとき復元できる。保存できなかったときは画面上部に赤で表示

### この版でできないこと（次の段階）
- 請求書・発注書への引き継ぎ（データは同じ構造なので、Phase 2 で見積から変換する）
- ログイン・権限・協力会社ごとのデータ分離・複数端末での共有（サーバーが必要。`docs/design/` の設計書を参照）
- 音声コマンドでの編集（「数量を10に変更」など）、図面の読み取り、オフライン専用モード
- 写真への注釈（矢印・寸法・マーカー）
- 見積比較（複数業者の見積を並べる画面）

## 製品の核
- **AIは金額を決めない。** 金額は「登録マスタ（商品・工事単価・人工・仕入価格）」と「固定の計算エンジン」だけで決まる
- 明細は自由文ではなく **マスタID＋数量＋単価** の構造化データで保存（`js/data.js` 冒頭にデータ構造）
- 見積画面には金額・単価を手で上書きできる欄がない。単価を変えるときはマスタを直す
- 外部サービス・有料ライブラリは不使用。オフラインで動く

## サイドバー
- 画面左端に固定した縦帯（展開時 252px）。メインエリア側の右上・右下の角を 28px 丸め、右端に半透明の青白い 1px の境界線
- 背景は半透明の濃紺 `rgba(13,20,38,.72)` ＋ `backdrop-filter: blur(18px) saturate(140%)` のガラス質。うっすらした影と内側のハイライトで浮かせる
- 項目はアイコン＋文字で均等に並ぶ。5つの親メニューはそのままで、「書類一覧」「新規作成」「設定・マスタ」は子メニューがスライド＋フェードで展開（0.3秒・ease-out）。開いている親は青い文字・アイコンで分かる。開閉の状態は次回も残る
- 現在の画面は、左端の青い縦バー＋淡い青の背景。子メニューにも印が付く
- ホバーで背景が淡く青くなり、アイコンと文字が 3px 右へ（0.2秒）。クリックで一瞬 0.98 に沈む。開いた直後はメニューが上から 0.04 秒ずつ時間差でフェードイン
- 一番下に丸いアバター（頭文字）＋名前＋役職（上に細い区切り線）。押すとプロフィール編集などのメニュー
- アクセントは #3B82F6〜#60A5FA。スマホ幅ではアイコンだけの細い帯

## 背景と動き
- 背景はネオン配色（シアン・ブルー・バイオレット・マゼンタ・ミント）のオーロラ。光の帯が 1周 78〜140 秒でとてもゆっくりうねる（`css/aurora.css`）。CSS の transform アニメーションだけで動かし、すりガラスと重ねても 60fps を保つ（画面より大きな回転レイヤーは重くなるので使わない）
- 各ステーション（パネル）はすりガラス：半透明＋`backdrop-filter: blur(24px) saturate(165%)` で後ろのオーロラがぼやけて透ける
- カーソルを合わせると：パネルの中をネオンの光がカーソルに付いてくる／カードがふわっと浮いて少し傾く／アイコンが跳ねる・回る／ボタンが光り、メインボタンはグラデーションが流れる／表の行に左からネオンのラインが走る／フォルダのふたが開く
- クリックすると：押した場所からネオンの輪と粒が弾け、押したカードやボタンが小さく弾む
- OS の「視差効果を減らす」設定ではオーロラと粒を止める。印刷・PDF には出ない

## 同じ現場に複数の見積（パターン別）
- 1つの現場（案件）に、条件や仕様を変えた見積を「A案・B案…」のパターンとして何枚でも作れる。それぞれ独立した見積書（番号・保存・送信前チェック・PDF出力・発行確定が別々）
- 見積画面の「パターン名」に名前を付ける（A案、グレードアップ案など自由）。「この見積をもとに別パターン」で、明細を写した次のパターン（次の空いている「〇案」）を作れる。単価は最新のマスタ
- 「現場ページ」（顧客・案件の案件、担当者ファイルの現場、見積画面から開く）：その現場の見積をカードで並べ、チェックしたパターンを比較表で比べる。明細をマスタ品目でそろえ、数量・金額が違う行に色が付く。小計・消費税・合計（いちばん安い案との差）・粗利率も並ぶ
- PDF のタイトルは「御見積書（A案）」のようにパターン名が入る。同じ現場で同じパターン名が重なると送信前チェックで知らせる
- 「修正見積」（同じ見積の新しい版）とは別の機能

## アイコンと形
- アイコンはポップで丸いシルエット：太めの線（2.1）・丸い線端と角・角丸の図形で描き直し（`js/ui.js` の `I`）。色は文字色（currentColor）のまま
- ボタンはカプセル形、アイコンだけのボタン・アイコンの箱・アバターはまんまる。パネル・入力欄・カード・フォルダの角も大きく丸める（`css/pop.css`）
- 透け感（すりガラス）・オーロラ・配色は変えていない。家紋のロゴは正式なデザインなので変えていない

## 担当者のファイル
- 見積を作る人・現場を担当する人の名簿（設定・マスタ →「担当者」）。名前・役割・色を登録
- ホームの「担当者のファイル」に、担当者の人数分のフォルダが並ぶ。開くとその人の**担当現場ごと**に書類がまとまり（担当現場・書類・下書き・今月の見積額）、「この現場で見積を作る」でそのまま新規作成できる
- 見積には「担当者」を記録（見積画面の基本情報で変更可）。案件（現場）にも担当者を付けられる。書類一覧は担当者で絞り込める
- サイドバー下の名前から「担当者を切り替え」ると、新しく作る見積がその人の担当になる
- 以前のデータは、それまでの利用者を最初の担当者にして、担当者の無い書類・案件をその人に割り当てる。担当者を名簿から消しても書類は消えず「未割り当て」のフォルダに移る
- ログインのない1台用のため、担当者にパスワード・権限はない（複数人での利用は `docs/design/` の設計書の範囲）

## 使いやすくした点
- 明細の追加はキーボードだけで完結：`/` で検索欄 → 品名やコードを入力 → `Enter` → 数量を入力 → `Enter` で検索欄に戻る
- 数量欄は `↑` `↓` で行移動。`Ctrl+S` 保存、`Ctrl+P` PDF出力、`Alt+1〜5` でメニュー切り替え
- 有効期限は「+14日 / +30日 / +60日 / +90日」をワンクリック
- 行の削除・パッケージ追加は「元に戻す」ができる
- 見積画面から顧客をその場で登録できる。案件を選ぶと件名が自動で入る
- 保存していない変更があるまま画面を離れようとすると確認が出る
- 複製すると単価を最新のマスタに合わせる。古い見積の単価がマスタと違うと行が黄色くなり「最新単価に更新」できる（自動では変えない）

## 計算エンジン（`js/engine.js`）
- 金額は円の整数、数量は小数2桁まで（浮動小数の誤差が出ない整数計算）
- 明細金額＝数量×単価（端数処理は設定で 切り捨て／四捨五入／切り上げ）
- 消費税はインボイス制度どおり **1書類につき税率ごとに1回だけ** 端数処理。税区分は 10% / 8%（軽減）/ 非課税 / 対象外
- 粗利＝税抜小計−原価合計、粗利率
- 改正建設業法第20条用に、原価区分（材料費・労務費・外注費・経費・その他）ごとの内訳を集計
- 発行確定した見積は、確定時の計算ルールで固定される

## 送信前チェック（`js/check.js`）
PDFを出す前に自動で調べ、怪しい箇所を「要修正／注意／参考」で一覧表示します。**書類は勝手に直しません。** 各項目の「該当箇所」から入力欄へ移動できます。

- 金額：保存時の金額と再計算の不一致、計算できない明細、合計0円以下、粗利率が下限未満、原価割れの行
- 宛先：顧客未選択・削除済み、敬称なし、法人なのに「様」、住所未登録、案件と顧客の食い違い、件名なし
- 日付：発行日なし・先日付・古い日付、有効期限なし・発行日より前・期限切れ・残り7日未満・長すぎ
- 明細：0行、マスタ未紐づけ・削除済み・使用停止、数量0/マイナス、単価がマスタと違う、同じ品目の重複
- 法令：登録番号（T＋13桁）の形式・未設定、自社名なし、工事なのに材料費・労務費の内訳がない（建設業法20条）
- 番号：見積番号の重複

## PDF出力（`js/print.js`）
プレビューを確認 →「PDFとして保存 / 印刷」→ 印刷画面で送信先を「PDFに保存」。
見積書には、発行者名・登録番号・発行日・宛名・税率ごとの対価と消費税額・軽減税率の※印・建設業法20条の内訳を載せます。

## 法令まわりのデータの持ち方
- インボイス制度：品目ごとに税区分、自社情報に登録番号、税は税率ごとに集計
- 電子帳簿保存法：発行確定した書類は編集・削除不可（変更は「修正見積」で新しい版を作り、元の版を残す）。履歴（作成・保存・発行確定・PDF出力）を記録。取引年月日・金額・取引先で検索できる
- 改正建設業法第20条：マスタごとに原価区分を持ち、見積とPDFに材料費・労務費などの内訳を出す

## 後から足せる構造
- **入力補助（AI等の有料オプション）**：`EE.plugins.registerInputAssist({ name, suggest })` で差し込める。拡張が返せるのは `[{ itemId, qty }]` の候補だけで、単価・金額は受け取らない
- **Phase 2（請求書・見積→請求の変換・入金管理）**：書類は `type` を持っているので、`type: 'invoice'` を足し、明細（マスタID＋数量＋単価）をそのまま引き継いで変換できる

## 起動アニメーション「静かに目覚める家紋」
- 約3秒：背景 → 外側の円環を時計回りに描く → 花びら5枚が順に出る → 中央の円と放射線・控えめな光 → 光の反射が一度だけ → 「桜ミツ」→「OUMITSU」・サブタイトル → クロスフェードでホーム
- 初回だけフル演出、2回目以降は短縮版（約1.3秒）。クリック・キー入力・「SKIP」で飛ばせる
- OS の「視差効果を減らす」設定では、完成した家紋とブランド名を静止画で短く表示
- SVG＋CSS のみ（ライブラリ・動画なし）。URL に `?splash=full` / `short` / `static` / `off` を付けると表示方法を指定できる。設定・マスタ →「データ・拡張」からフル演出を再生できる
- 家紋は提供された原本（`assets/crest-original.png`）の輪郭をそのままベクター化したもの（`tools/trace_crest.py`）。パーツ（円環・花びら5・萼5・中央の円）に分けてあり、放射状の線は花びらの切り込みとして原本どおりに含まれる。原本と同じ見え方になるよう「明るい円形の地に濃い家紋」で表示する（色は `css/splash.css` の `--field` / `--crest`）

## 注意
- データはブラウザ内（localStorage）、取り込んだ原本は IndexedDB に保存されます。「すべて書き出し（JSON）」には原本ファイルは含まれません。ブラウザのデータ消去で消えるので、設定・マスタ →「データ・拡張」から定期的に書き出してください
- 初回はサンプルデータで起動します（「サンプルに戻す」「すべて削除」も同じ画面）
