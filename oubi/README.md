## 保存先

業務管理と同じ Supabase の `docs` 表に、種類（col）を分けて入れる。表を新しく作る必要はない。

| col | id | 中身 |
|---|---|---|
| `mitsu` | `master` | 品目マスタ・テンプレート・計算式・定型文・計算の決まり・ロゴ・会社印など |
| `mitsu_docs` | 書類ID | 見積書1通ずつ（同時に別の見積を直しても上書きし合わない） |
| `mitsu_home` | 社員ID | その人のウィジェットの並び・お気に入り |
| `cases` | 工事ID | 今までの工事。見積から書き戻すのは `quote`（明細・金額など）、`plan`（収支書）、`mitsu`（採用した見積・現場メモ） |

会社名・住所・電話・登録番号・振込先・代表者は、業務管理の設定（`settings/main` の `company`）と同じものを使う。

**公開したら最初に確かめること**：見積を1つ保存して、「見積を保存できませんでした（保存先の許可がありません）」が出ないか。
出たら、Supabase の `docs` 表の書き込みの決まり（Row Level Security）が、col の名前で制限している可能性がある。
Supabase の SQL Editor で次を実行すると、今の決まりを読める（読むだけで、何も変えない）：

```sql
select policyname, cmd, qual, with_check from pg_policies where tablename = 'docs';
```

## 作り方・公開のしかた

```sh
node oubi/tools/build-mitsu.js      # 桜ミツ（easy-estimate）を直したら：mitsu.js・mitsu.css を作り直す
sh oubi/tools/package.sh            # 公開用の zip（oubi-公開用.zip）を作る。テスト・道具は入れない
```

zip を Netlify の Deploys に置くと公開される。vendor/（PDF・画像の読み取り）を含むので約11MB。

- `mitsu.js` … 桜ミツのプログラムを1つにまとめたもの（自動生成）
- `mitsu.css` … 桜ミツの見た目。すべて `.ee` の中だけに効くよう書き換え、明るい画面用の色も自動で作る（自動生成）
- `mitsu-bridge.js` … つなぎ（保存先・工事との変換・画面の切り替え）
- `mitsu-host.css` … 見積の画面を業務管理の中に置くための見た目
- `theme-oumitsu.css` … 業務管理の見た目を桜ミツに合わせる

## テスト

リポジトリの最上位で `python3 -m http.server 8765 --bind 127.0.0.1` を動かしてから：

```sh
node oubi/tests/integration.js   # つなぎの確認（工事→見積→工事、顧客の登録、2人同時、スマホ幅）
node oubi/tests/trial.js         # 試用モード（この端末だけ）
node oubi/tests/a11y.js          # 濃さと文字の大きさ（axe-core が必要）
node oubi/tests/monkey.js 10000  # ランダム操作
```

結果（2026-11-19）：integration 全項目合格・trial 合格・a11y 濃さ不足0／14px未満0（12画面×暗い/明るい×パソコン/スマホ）・
ランダム操作1万回は1回目に2種類の失敗（直した）、2回目は途中で1つのタブが白いエラー画面に移り判定できず（原因不明・同じ条件の3回目では起きず）、3回目は失敗0。

テストは `tests/mock-supa.js`（共有モードのまね）を使い、本番の Supabase には一切つながない。
本番の Supabase での動き（合言葉で入ったあと・本物の通信）は、合言葉を持っていないので試していない。
