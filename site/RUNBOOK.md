# RUNBOOK(AI編集長の毎日の手順)

## 目的
Excel・スプレッドシートの実務記事を、「動かして確かめた」品質で、毎日少しずつ公開する。量ではなく、検証済みの正確さと独自性で評価される状態を作る。

## 守ること(破ると公開しない)
1. 数式・手順は、実際に計算して確認したものだけを書く(LibreOfficeで再計算)。確認できないものは書かないか、「未確認」と明記する。
2. 事実・仕様の主張には、公式ドキュメント等の出典URLを付ける。出典は、取得して中身を確認したものだけ。
3. 他サイトの文章を写さない。自分で作った例・表・数式で説明する。
4. XLOOKUP・FILTER・UNIQUE・SORT など、LibreOffice環境で正しく確認できない関数は、確認方法が確立するまで扱わない。
5. 健康・お金の運用・法律など、誤りの影響が大きい分野は扱わない。
6. 収益保証・誇大表現は使わない。アフィリエイトを入れる場合は、記事冒頭に『広告』『PR』を明記する。
7. 1日の公開は記事最大6本・無料ツール最大3本(2026-10-13増量)。品質ゲート(quality_check.py)が通らない記事は公開しない。

## 毎日の手順
1. `topics.csv` から、statusが todo で priority が最小の1〜2件を選ぶ。
2. 調査: Web検索で、公式ドキュメントと検索意図(読者が何に困っているか)を確認する。出典は WebFetch で中身を確認する。
3. 検証: `verify/` に、記事で使う数式を実際に計算するスクリプトを作る。期待結果と実際の結果が一致するか確認する。一致しない場合は、記事の主張を修正する。
4. 執筆: `content/YYYY-MM-DD-slug.md` に書く。front matterの必須項目(title, description, date, category, slug, sources, verified, verification_note)を埋める。冒頭で結論、見出し(##)で構造化、実例の表と数式を入れる。
5. 品質ゲート: `python3 quality_check.py` → NGなら直す。直らなければ公開しない。
6. 生成: `python3 build_site.py` → `dist/` を更新する。
7. 公開: `dist/` を、公開先(Cloudflare Pages)に連携したGitHubリポジトリへ反映する。※権限がない場合は、`dist/` を成果物として保存し、HUMAN_TASKS.mdにアップロードの依頼を書く。
8. 記録: `topics.csv` のstatusを更新し、`pdca/LOG.md` に追記する。

## 週次(日曜)
- Search Consoleの実績(表示回数・クリック・平均掲載順位・インデックス状況)が INBOX.md に貼られていれば、読み取って記事ごとに判定する。
  - 表示回数が増えない、またはインデックスされない記事: 見出し・導入・内部リンクを改善する。
  - 表示はあるがクリックされない記事: titleとdescriptionを改善する。
  - 順位が上がっている記事: 関連記事を追加する(同じ検索意図の深掘り)。
- 公開済みの記事を、年1回以上見直す(関数の仕様変更、出典の更新)。
- 記事が8〜15本たまり、必須ページが整い、実績が出てきた時点で、AdSenseやアフィリエイトの申請時期をHUMAN_TASKS.mdに書く。

## データがないとき
- Search Consoleは、公開後の反映に時間がかかる。7日分のデータがないうちは、記事の良し悪しを判断しない。
- 「データ不足」を理由に、品質の基準を下げない。基準を満たす記事を、毎日積み上げる。
