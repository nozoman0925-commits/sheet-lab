「請求書は出したけれど、来月いくら入ってくるのか、すぐには答えられない」——材料や外注の支払いが重なる月に、手元の現金が足りるかを考えるとき、必要なのはこの数字です。請求書ごとの**入金予定日**がわかっていれば、未入金の分を月ごとに足すだけで、月別の入金予定が出せます。

この記事では、請求書を1行ずつ(請求番号・取引先・請求額・入金予定日・入金日)入れ、**基準日の月から12か月分の入金予定額**を出す式を示します。入金予定日を過ぎてまだ入金されていない分は、月別には入れず「期限超過」として別に数えます(予定の月に入れると、今後入る金額が実際より多く見えるためです)。

出典: 筆者がLibreOfficeで計算して確認(検証スクリプト: site/verify/cash_forecast.py)。外部サイトの説明は参照していません。**Excelでは未確認**です。使うのはIF・OR・NOT・ISNUMBER・INT・COUNTIF・SUMIF・SUMIFS・SUMPRODUCT・DATE・YEAR・MONTH・EDATEという一般的な関数ですが、本番で使う前に、数行を手計算と見比べてください。この記事は表の作り方の説明です。入金予定日は、取引先との支払条件から決めた日をそのまま入れる前提で、**実際に入金されるかどうかや、資金繰り全体の判断は、この表だけでは決まりません**。

## 先に結論: 未入金で期限内の行だけ「予定月」を作り、SUMIFSで月ごとに足す

- 入金日が入っている行 → **入金済**。月別には入れない
- 入金日が空欄で、入金予定日が基準日より前 → **期限超過**。件数と金額を別に出す
- 入金日が空欄で、入金予定日が基準日の当日以降 → **入金待ち**。入金予定日の「月の1日」を予定月にする
- 月別の表は、基準日の月から12か月分を `EDATE` で並べ、`SUMIFS` で予定月が一致する行の請求額を足す

予定月を「その月の1日」にそろえるのがコツです。日付を範囲で比べるより、月の1日どうしの一致で数えるほうが、月末日(10/31)と月初(11/1)の取り違えが起きにくくなります。

入金予定日を何日にするかは、[請求書の支払期限を締め日と支払条件から出す記事](/payment-due/)の式がそのまま使えます。入金されたあとの照合は[入金と請求の照合の記事](/payment-match/)に、期限を過ぎた分の日数別の集計は[未入金を経過日数別に集計する記事](/receivable-aging/)にあります。

## Excelの式

シート名は「入金予定」。2行目から使います。

| 列 | 内容 | 入れるもの |
|---|---|---|
| A | 請求番号 | 手入力(例: S-001) |
| B | 取引先 | 手入力 |
| C | 請求額 | 手入力(1以上の整数。税抜か税込のどちらかにそろえる) |
| D | 入金予定日 | 手入力(日付) |
| E | 入金日 | 入金されたら手入力(日付)。未入金は空欄 |
| F | 状態 | 式 |
| G | チェック | 式 |
| H | 予定月 | 式(月の1日) |
| K2 | 基準日 | 日付(例: 2026/10/15。今日の日付にしたいときは `=TODAY()` でもよい) |

```
G2: =IF(A2&B2&C2&D2&E2="","",IF(A2="","請求番号が空欄",
      IF(COUNTIF($A$2:$A$1000,A2)>1,"請求番号が重複",
      IF(C2="","請求額が空欄",IF(NOT(ISNUMBER(C2)),"請求額が数字でない",
      IF(OR(C2<1,C2<>INT(C2)),"請求額は1以上の整数",
      IF(D2="","入金予定日が空欄",IF(NOT(ISNUMBER(D2)),"入金予定日が日付でない",
      IF(OR(D2<1,D2<>INT(D2)),"入金予定日が日付でない",
      IF(E2="","",IF(NOT(ISNUMBER(E2)),"入金日が日付でない",
      IF(OR(E2<1,E2<>INT(E2)),"入金日が日付でない",""))))))))))))
F2: =IF(OR(G2<>"",A2&B2&C2&D2&E2=""),"",IF(E2<>"","入金済",
      IF(NOT(ISNUMBER($K$2)),"基準日を入力",IF(D2<$K$2,"期限超過","入金待ち"))))
H2: =IF(F2="入金待ち",DATE(YEAR(D2),MONTH(D2),1),"")
```

D・E・K2列は「日付」の表示形式、H列は「yyyy/mm」の表示形式、C列は「数値(桁区切り)」にします。

件数と金額のまとめ(K〜N列。範囲は1000行まで)です。

```
K5: =COUNTIF($F$2:$F$1000,"期限超過")                         ← 期限超過の件数
K6: =SUMIF($F$2:$F$1000,"期限超過",$C$2:$C$1000)             ← 期限超過の金額
K7: =SUMIF($F$2:$F$1000,"入金待ち",$C$2:$C$1000)             ← 入金待ちの金額(全期間)
K8: =SUMPRODUCT(--(LEN($G$2:$G$1000)>0))                     ← チェックが出ている行数

L2:  =IF(ISNUMBER($K$2),DATE(YEAR($K$2),MONTH($K$2),1),"")
L3:  =IF(L2="","",EDATE(L2,1))                                 (L13まで下にコピー)
M2:  =IF(L2="","",COUNTIF($H$2:$H$1000,L2))                    ← 件数
N2:  =IF(L2="","",SUMIFS($C$2:$C$1000,$H$2:$H$1000,L2))        ← 入金予定額   (M2〜N2を13行目までコピー)
M14: =IF(L2="","",SUM(M2:M13))     N14: =IF(L2="","",SUM(N2:N13))
M15: =IF(L2="","",COUNTIF($F$2:$F$1000,"入金待ち")-M14)        ← 12か月より先の件数
```

L列は「yyyy/mm」の表示形式にします。基準日が空欄や文字のときは、月別の表を空にします(エラーは出しません)。

## 実際に計算して確認した結果

基準日を2026/10/15にして、7件を入れたときの確認です。

| 請求番号 | 請求額 | 入金予定日 | 入金日 | 状態 |
|---|---|---|---|---|
| S-001 | 800,000 | 2026/09/15 | 空欄 | 期限超過 |
| S-002 | 300,000 | 2026/10/13 | 空欄 | 期限超過 |
| S-003 | 150,000 | 2026/10/18 | 空欄 | 入金待ち(10月) |
| S-004 | 500,000 | 2026/10/25 | 空欄 | 入金待ち(10月) |
| S-005 | 200,000 | 2026/11/14 | 空欄 | 入金待ち(11月) |
| S-006 | 700,000 | 2026/10/05 | 2026/10/06 | 入金済 |
| S-007 | 90,000 | 2028/02/27 | 空欄 | 入金待ち(12か月より先) |

| 月 | 件数 | 入金予定額 |
|---|---|---|
| 2026/10 | 2 | 650,000 |
| 2026/11 | 1 | 200,000 |
| 合計 | 3 | 850,000 |

期限超過は2件・1,100,000円、12か月より先の件数(M15)は1件で、入金待ちの金額(K7)は940,000円になりました。**月別の表だけを見ると850,000円ですが、期限超過の1,100,000円が入金されなければ、見込みはそこまで下がります**。そのため、期限超過は別枠で必ず見える位置に置きます。

入金予定日だけを変えて、基準日2026/10/15で1件を入れた結果です。

| 入金予定日 | 状態 | 入る月 |
|---|---|---|
| 2026/10/15(基準日と同じ日) | 入金待ち | 2026/10 |
| 2026/10/14(前日) | 期限超過 | - |
| 2026/10/16(翌日) | 入金待ち | 2026/10 |
| 2026/10/31(月末) | 入金待ち | 2026/10 |
| 2026/11/01(月初) | 入金待ち | 2026/11 |
| 2027/09/30(12か月目の最後の日) | 入金待ち | 2027/09 |
| 2027/10/01(13か月目の初日) | 入金待ち | 表の外(M15が1) |

基準日2026/12/20のときの2027/01/05は2027/01に、基準日2028/02/10のときの2028/02/29(うるう日)は2028/02に入りました。入金予定日が基準日と同じ日の行は、まだ過ぎていないので「入金待ち」にしています。

入力ミスの行は、状態と予定月を空欄にして、G列にこう出ます。

| 入力ミス | チェック |
|---|---|
| 請求番号が空欄 | 請求番号が空欄 |
| 請求番号が重複(S-001とs-001) | 請求番号が重複 |
| 請求額が空欄 | 請求額が空欄 |
| 請求額が「80万」・全角「８００，０００」 | 請求額が数字でない |
| 請求額が0・小数・マイナス | 請求額は1以上の整数 |
| 入金予定日が空欄 | 入金予定日が空欄 |
| 入金予定日が全角「２０２６/１０/２０」・0・時刻つき | 入金予定日が日付でない |
| 入金日が文字の「済」 | 入金日が日付でない |
| すべて空欄の行 | (何も出さない) |

入金日だけが入っていて入金予定日が空欄の行も、「入金予定日が空欄」で止めます。入金済の行を月別に入れないだけでなく、**入力の抜けを見逃さない**ためです。

30ケースすべて、状態・チェック表示と、期限超過・入金待ちの集計、12か月分の月別集計が、Pythonで計算した結果と一致しました。さらに、乱数で作った**500行**(請求番号の空欄・重複、入金予定日・入金日・請求額の文字・0・小数・マイナスを約10%混ぜ、約2割に入金日を入れました)でも、**全項目と月別集計(12か月分・合計・表の外の件数)が一致**しました。Excelでの確認はしていません。

## つまずきやすい点

- **入金されたのに入金日を入れ忘れる**: 入金日が空欄のままだと、いつまでも「入金待ち」や「期限超過」に残り、予定額が実際より多く見えます。通帳を見るタイミング(週に一度など)で入金日を入れる習慣にしてください。
- **期限超過が増えていないか**: K5が0でない月は、月別の予定額を鵜呑みにせず、先に取引先へ確認するのが安全です。
- **基準日を更新する**: 基準日が古いままだと、すでに過ぎた予定が「入金待ち」に残ります。`=TODAY()`を入れると開くたびに更新されますが、過去に保存した表の状態を見直したいときは日付を直接入れてください。
- **月をまたぐ分割入金**: 1つの請求を2回に分けて受け取る場合は、請求番号を分けて2行にしてください(例: S-001-1、S-001-2)。分割請求の残額の考え方は[分割請求の残額の記事](/split-billing-balance/)にあります。
- **12か月を超えるとき**: L列の月を13行目より下に増やし、M・N列の式をコピーします。合計の式の範囲(M2:M13など)も合わせて広げてください。
- **表の外の件数**: M15が0でないときは、12か月より先の予定です。必要なら基準日を後ろにずらして見直してください。

## 注意点: この記事ができないこと

- 支払い(材料・外注・給与など)の予定は扱いません。入金予定だけを月別に出す表です。
- 入金予定日は入力した日付をそのまま使います。取引先の支払遅れや、実際の入金のぶれは見込みません。
- 金額は整数だけを前提にしています。税の取り扱いは扱いません(請求額は、税抜か税込のどちらかにそろえて入れてください)。
- 振込手数料を引かれて入金された場合の差額の処理は扱いません。
- 資金繰りや借入れの判断、決算・税務の処理は扱いません。必要なら税理士や金融機関に相談してください。

## 見積から工事台帳までつなげたいとき

見積の計算そのものから作りたい場合は、運営者が作った[工事・リフォーム用 見積書テンプレート(Excel・980円)](/go/estimate-construction/?from=cash-forecast)があります。数量×単価(四捨五入)、諸経費率、値引き、消費税10%(切り捨て)、税込合計を自動計算し、明細は20行、A4縦1枚で印刷できます。**この記事の「入金予定の月別集計」機能は、この商品には入っていません**。工事台帳への転記、請求書への変換、軽減税率の混在、インボイス要件の保証もできません。Excelの確認はWindowsデスクトップ版16のみです。(これは運営者の商品の案内です。)

見積の合計だけをすぐ確かめたいときは、無料の[見積の合計計算ツール](/tools/estimate-total/)が使えます(入力は外部に送信されません)。

## まとめ

- 請求書ごとに請求額・入金予定日・入金日を入れ、入金日が空欄で期限内の行だけ、入金予定日の月の1日を「予定月」にする
- 月別の表は、基準日の月から`EDATE`で12か月並べ、`SUMIFS`で予定月が一致する行の請求額を足す
- 入金予定日を過ぎた未入金は「期限超過」として別に数え、月別の予定には入れない
- 請求額・日付の入力ミス(空欄・文字・全角・0・マイナス)はチェック列で止め、予定額に混ぜない
- 30ケースと500行の照合はLibreOfficeで一致。Excelでは未確認のため、本番では数行を手計算で見比べる
