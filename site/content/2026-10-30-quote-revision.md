施主から「やっぱりこの工事も入れて」「予算に合わせて少し下げて」と言われて、見積を出し直す。そのたびに行を足していくと、半月後には同じ工事の見積が3行あり、**どれが最新で、いくらで契約するのか**がすぐに答えられなくなります。台帳や請求書に転記するときに古い版の金額を拾ってしまうのは、この状態から起きます。

この記事では、見積の履歴を1行ずつ(工事番号・版・見積額・提出日)入れ、**工事ごとに最新版と旧版を自動で判定**し、最新版だけの件数と合計、初版からの増減を出す式を示します。版の入れ間違いや提出日の逆転は、チェック列で止めます。

出典: 筆者がLibreOfficeで計算して確認(検証スクリプト: site/verify/quote_revision.py)。外部サイトの説明は参照していません。**Excelでは未確認**です。使うのはIF・AND・OR・NOT・ISNUMBER・INT・COUNTIF・COUNTIFS・SUMIF・SUMIFS・SUMPRODUCT・MAXIFS・MINIFSという関数で、**MAXIFSとMINIFSはExcel 2019以降(Microsoft 365を含む)の関数**です。Excel 2016以前では使えません。本番で使う前に、数行を手計算と見比べてください。この記事は表の作り方の説明で、**どの版が実際に契約されたかは、この表では決まりません**(契約した版は、契約書や注文書で確認してください)。

## 先に結論: 「その工事の中で一番大きい版番号」を探し、自分の版と比べる

- 版は、1, 2, 3 と手で入れる(第1版=1)。見積書に「第2版」と書く運用にそろえる
- 同じ工事番号の行のうち、チェックが通った行の版番号の最大値を `MAXIFS` で出す
- 自分の版がその最大値なら **最新版**、そうでなければ **旧版**
- 最新版の行には、同じ工事の初版からの増減(最新版−初版)を出す

日付の新しさではなく**版番号で最新を決める**のがコツです。提出日で決めると、同じ日に2版を出した場合や、日付を打ち間違えた場合に最新を取り違えます。その代わり、版番号と提出日が食い違う行(新しい版なのに提出日が前)は、チェック列で止めます。

見積を出す前の「提出後に返事が来ない案件」の管理は[見積提出後の回答待ちの記事](/quote-followup/)に、契約後に見積の明細を台帳に渡す方法は[見積の明細から台帳に渡す記事](/quote-to-ledger/)に、契約後の金額の変更の記録は[契約金額の変更を管理する記事](/contract-change/)にあります。

## Excelの式

シート名は「見積履歴」。2行目から使います。

| 列 | 内容 | 入れるもの |
|---|---|---|
| A | 工事番号 | 手入力(例: A-001) |
| B | 版 | 手入力(1以上の整数。第1版=1) |
| C | 見積額 | 手入力(1以上の整数。税抜か税込のどちらかにそろえる) |
| D | 提出日 | 手入力(日付) |
| F | 状態 | 式(最新版/旧版) |
| G | チェック | 式 |
| H | 有効な版 | 式(チェックが通った行だけ版番号を入れる作業列) |
| I | 初版からの増減 | 式(最新版の行だけ) |

```
G2: =IF(A2&B2&C2&D2="","",IF(A2="","工事番号が空欄",IF(B2="","版が空欄",
      IF(NOT(ISNUMBER(B2)),"版が数字でない",IF(OR(B2<1,B2<>INT(B2)),"版は1以上の整数",
      IF(C2="","見積額が空欄",IF(NOT(ISNUMBER(C2)),"見積額が数字でない",
      IF(OR(C2<1,C2<>INT(C2)),"見積額は1以上の整数",
      IF(D2="","提出日が空欄",IF(NOT(ISNUMBER(D2)),"提出日が日付でない",
      IF(D2<>INT(D2),"提出日が日付でない",
      IF(COUNTIFS($A$2:$A$1000,A2,$B$2:$B$1000,B2)>1,"同じ工事の同じ版が重複",
      IF(COUNTIFS($A$2:$A$1000,A2,$B$2:$B$1000,"<"&B2,$D$2:$D$1000,">"&D2)>0,
          "前の版より提出日が前",""))))))))))))
H2: =IF(AND(G2="",A2&B2&C2&D2<>""),B2,"")
F2: =IF(OR(G2<>"",A2&B2&C2&D2=""),"",IF(B2=MAXIFS($H$2:$H$1000,$A$2:$A$1000,A2),"最新版","旧版"))
I2: =IF(F2="最新版",C2-SUMIFS($C$2:$C$1000,$A$2:$A$1000,A2,$H$2:$H$1000,MINIFS($H$2:$H$1000,$A$2:$A$1000,A2)),"")
```

B列は「標準」、C列は「数値(桁区切り)」、D列は「日付」の表示形式にします。F・G・H・I列は2行目の式を1000行目までコピーします。

まとめの式(K列)です。

```
K4: =COUNTIF($F$2:$F$1000,"最新版")                       ← 最新版の件数(=工事の数)
K5: =SUMIF($F$2:$F$1000,"最新版",$C$2:$C$1000)           ← 最新版の見積額の合計
K6: =COUNTIF($F$2:$F$1000,"旧版")                         ← 旧版の件数
K7: =SUM($I$2:$I$1000)                                    ← 初版からの増減の合計
K8: =SUMPRODUCT(--(LEN($G$2:$G$1000)>0))                  ← チェックが出ている行数
```

`MAXIFS`・`MINIFS`は、Excelのファイルに保存されるときは内部で`_xlfn.`が付いた形になります。Excelで式を入力するときは、そのまま`MAXIFS(`と打てば使えます。

## 実際に計算して確認した結果

3つの工事の履歴6行を、わざと順番をばらして入れたときの確認です。

| 行 | 工事番号 | 版 | 見積額 | 提出日 | 状態 | 初版からの増減 |
|---|---|---|---|---|---|---|
| 2 | A-001 | 1 | 1,000,000 | 10/01 | 旧版 | |
| 3 | A-002 | 1 | 300,000 | 10/02 | 旧版 | |
| 4 | A-001 | 2 | 1,150,000 | 10/08 | 旧版 | |
| 5 | A-002 | 2 | 280,000 | 10/07 | 最新版 | -20,000 |
| 6 | A-001 | 3 | 980,000 | 10/13 | 最新版 | -20,000 |
| 7 | A-003 | 1 | 90,000 | 10/03 | 最新版 | 0 |

最新版の件数(K4)は3、見積額の合計(K5)は1,350,000円、旧版(K6)は3件、初版からの増減の合計(K7)は-40,000円になりました。**A-001は第2版で1,150,000円まで上がり、第3版で980,000円に下がっています**。行を足しただけの表だと、一番大きい金額や一番下の行を拾ってしまいがちですが、この式は版番号3の行(980,000円)を最新版にします。

このほか、次のことを確認しています。

- 行の順番が逆(第2版が上、第1版が下)でも、最新版は変わらない
- 版が飛んでいる(第1版と第3版だけ)ときは、第3版が最新版で、初版は第1版になる
- 同じ日に第1版と第2版を出しても、版番号が大きい第2版が最新版になる
- 工事番号の大文字と小文字の違い(A-001とa-001)は同じ工事として数える
- 1つの工事の入力ミスは、別の工事の判定に影響しない

入力ミスの行は、状態と増減を空欄にして、G列にこう出ます。

| 入力ミス | チェック |
|---|---|
| 工事番号が空欄 | 工事番号が空欄 |
| 版が空欄 | 版が空欄 |
| 版が全角「２」 | 版が数字でない |
| 版が0・1.5・マイナス | 版は1以上の整数 |
| 見積額が空欄 | 見積額が空欄 |
| 見積額が「70万」 | 見積額が数字でない |
| 見積額が0・小数 | 見積額は1以上の整数 |
| 提出日が空欄 | 提出日が空欄 |
| 提出日が全角「２０２６/１０/５」・時刻つき | 提出日が日付でない |
| 同じ工事の同じ版が2行 | 同じ工事の同じ版が重複(2行とも) |
| 第2版の提出日が第1版より前 | 前の版より提出日が前(第2版の行) |
| すべて空欄の行 | (何も出さない) |

30ケースすべて、状態・チェック表示・初版からの増減と、最新版の件数・合計、旧版の件数、増減の合計、チェック行数が、Pythonで計算した結果と一致しました。さらに、乱数で作った**500行**(約120工事、版番号・金額・提出日をそろえたうえで、入力ミスや提出日の逆転を約10%混ぜ、行の順番を入れ替えた)でも、**全項目とまとめの数字が一致**しました。Excelでの確認はしていません。

## つまずきやすい点

- **チェックが出ている工事の「最新版」は信用しない**: たとえば第3版の提出日が第2版より前だと、第3版の行がチェックで止まり、**第2版が最新版と表示されます**。表の上では正しく見えるのに、本当の最新は第3版です。K8(チェックが出ている行数)が0でないときは、先にチェック列を直してから最新版を見てください。
- **版番号の付け方をそろえる**: 「第2版」「改訂」「R2」など書き方がばらばらだと入力ミスの元です。見積書の右上に「第○版」と入れ、その数字をそのまま入れる運用にします。
- **同じ版を直しただけのとき**: 金額の誤字を直して再提出する場合も、版を上げるか、元の行を直して履歴を残さないかを決めておきます(同じ版を2行にすると「重複」で止まります)。
- **契約した版がどれか**: 最新版が契約版とは限りません。「最新の見積」と「契約した見積」は別の列(契約した版の番号)で管理し、台帳には契約した版の金額を渡してください。
- **工事番号を変えない**: 途中で工事番号を付け替えると、別の工事として数えられ、旧版が見つからなくなります。
- **Excel 2016以前**: MAXIFS・MINIFSが使えません。使える環境で確認するか、版の列を並べ替えて一番下の行を最新とする運用にしてください(この記事では確認していません)。

## 注意点: この記事ができないこと

- どの版が契約されたか、施主が承諾したかは扱いません。
- 見積額の中身(数量・単価・諸経費)の計算は扱いません。見積額は合計を入れる前提です。
- 税の扱い(税抜・税込)は、入力する側でそろえる前提で、式では見ません。
- 版を飛ばした入力(第1版と第3版だけ)は、そのまま受け付けます。抜けを見つけたいときは、別に版の連番を確認してください。
- 1000行を超える履歴は、式の範囲(`$1000`)を広げる必要があります。

## 見積から工事台帳までつなげたいとき

見積の計算そのものから作りたい場合は、運営者が作った[工事・リフォーム用 見積書テンプレート(Excel・980円)](/go/estimate-construction/?from=quote-revision)があります。数量×単価(四捨五入)、諸経費率、値引き、消費税10%(切り捨て)、税込合計を自動計算し、明細は20行、A4縦1枚で印刷できます。**この記事の「改訂版から最新版を拾う」機能は、この商品には入っていません**。工事台帳への転記、請求書への変換、軽減税率の混在、インボイス要件の保証もできません。Excelの確認はWindowsデスクトップ版16のみです。(これは運営者の商品の案内です。)

見積の合計だけをすぐ確かめたいときは、無料の[見積の合計計算ツール](/tools/estimate-total/)が使えます(入力は外部に送信されません)。

## まとめ

- 見積の履歴は、工事番号・版・見積額・提出日を1行ずつ入れ、行を消さずに足していく
- 最新版は、同じ工事の「チェックが通った行の最大の版番号」と自分の版が一致する行(`MAXIFS`)
- 最新版の行には、初版からの増減(最新版−初版)を出す。最新版だけの合計も出せる
- 版・見積額・提出日の入力ミスと、同じ版の重複、提出日の逆転は、チェック列で止める
- チェックが出ている工事の「最新版」は信用しない。30ケースと500行の照合はLibreOfficeで一致、Excelでは未確認
